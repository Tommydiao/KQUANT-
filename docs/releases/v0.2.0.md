# KQUANT v0.2.0 — OSS Baseline

KQUANT v0.2.0 is the first release prepared as a public open-source baseline. It packages the current US equities and crypto research terminals behind a documented, research-only architecture with explicit safety boundaries.

> KQUANT is research software. It does not connect to trading accounts, place orders, sign wallet transactions or grant an LLM execution authority.

## Highlights

- **US Stock Terminal** — read-only Longbridge market data, transparent features, manual research workflow and reproducible strategy validation.
- **KQUANT CRYPTO** — public CEX/DEX/on-chain evidence paths, Data Trust, factors, deterministic EVAL review, Paper/Shadow observations and advisory alerts.
- **Unified local workspace** — one shell/health surface while stock and crypto runtimes keep independent APIs, databases and sessions.
- **Deterministic safety authority** — LLM output is advisory and cannot override evidence gates, EVAL decisions or research-only boundaries.
- **Verification** — backend/frontend tests, GitHub Actions, tracked-secret scanning and explicit read-only boundary checks.
- **OSS documentation** — MIT License, contributor guide, security policy, code of conduct, public roadmap and architecture overview.

## Architecture principle

KQUANT separates generated research from authoritative validation:

```text
market evidence -> data trust -> factors -> strategy/signal proposal
               -> deterministic validation / EVAL -> research output
                                      ^
                               LLM advisory only
```

Generated explanations may help inspect evidence, but they do not create permission to trade.

## Known limitations

- The project remains local-first and Windows-oriented in several launch paths.
- The unified gateway is not yet a production single-origin reverse proxy.
- Some realtime providers require user-supplied credentials in local `.env` files.
- Historical and prospective evidence coverage varies by provider and asset; missing evidence remains explicit rather than being inferred.
- Research validation does not imply future returns or real-money readiness.

## Upgrade notes

This release is intended as an OSS baseline rather than a trading-system migration. Existing local runtime databases and private `.env` files should remain outside version control. Review provider configuration before enabling realtime collection.
