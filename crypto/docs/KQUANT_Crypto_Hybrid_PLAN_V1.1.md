## 1. 项目目标与边界

将当前双模式研究候选升级为可解释、可复现、可审计的混合智能研究系统，明确结合：

1. 传统技术分析：识别行情结构，产生具备明确保护价格的候选交易。
2. LLM：将新闻、公告及解释性信息转化为有来源的结构化事件。
3. 贝叶斯分析：估计候选净收益优势，表达参数与预测不确定性。
4. 蒙特卡罗模拟：评估给定持仓方案下的组合路径、回撤及尾部风险。
5. 独立风险控制：决定能否新增风险及最大数量，不能被模型绕过。

**交付目标是“完整研究与候选模拟闭环”，不是承诺增加 AI 后盈利。技术内核负责机会定义，贝叶斯负责优势评估，蒙特卡罗负责路径风险，独立风控负责最终边界；不得将它们做成简单投票器。**

### 1.1 本期范围

- 延续 BTCUSDT、ETHUSDT、SOLUSDT 现货研究。
- 延续 1H 行情识别、5m 信号触发，上涨趋势与震荡两类做多策略。
- 初期保留原止损、止盈、持仓期限、持仓上限、成本和保护处理顺序。
- 支持历史研究、事件回放、公共行情候选模拟及只读展示。
- 新增版本、模型、事件数据、资金状态与评估记录采用独立命名空间和存储。
- 本版对“模型延迟后如何成交”新增显式时序合同；原技术基线保持原行为，延迟版以独立执行政策和对照运行，不静默改变旧结果。

### 1.2 本期不做

- 不自动接入实盘，不新增合约空头、杠杆、马丁格尔、摊平或强化学习下单。
- 不重构股票侧，不把热点板块/股票/期权总方案混入本期。
- 不为升级随意停止公共采集器或原服务，不抢占原 writer lease。
- 不重写既有不可变回放结果，不把已暴露历史重新切分后称为未见测试集。
- 不允许 LLM 修改资金、止损、目标价、风险限额、执行准入或配置文件。
- 不把已有模块更名后宣称“训练完成”“概率已校准”或“有交易优势”。
- 不因为模型不可用而在同一 run 静默切回技术交易；实验臂必须有固定身份。

### 1.3 本期完成与后续实盘的关系

工程、数据、模型、收益四类结论独立。工程通过可交付研究工具，不能自动获得候选筛选权限，更不能获得实盘权限。样本不足时交付可复现系统和不足说明，不强制产生交易。

## 3. 目标架构

### 3.1 两条决策通道，一个账本写入者

```text
市场 OHLCV / 实时报价                      授权公告与新闻
        |                                         |
        v                                         v
可信输入日志：来源、首次接收、排序、去重       文档仓库 + 受限 LLM 工作器
        |                                         |
        |                                  校验/去重后的事件仓库
        |                                         |
        +----------------------+                  |
        |                      |                  |
        v                      v                  |
保护通道（高优先级）       新仓通道                |
已有持仓/待退出           完整同步市场批次          |
原止损/止盈/超时          原双模式技术内核           |
模式失效/日界硬风险       原始技术候选               |
有效报价下退出或挂起       冻结智能特征快照 <---------+
        |                      |
        |                 贝叶斯净 R 评估
        |                      |
        |                 离散仓位方案
        |                      |
        |                 蒙特卡罗组合风险
        |                      |
        |                 时效/组合版本/最终硬风控复核
        |                      |
        +----------+-----------+
                   |
                   v
          单一串行组合账本写入者
        指令/预留/成交/状态/checkpoint 原子提交
                   |
                   v
          审计、报告、恢复、只读页面
                   |
                   v
          LLM 解释（只读已冻结结果）
```

### 3.2 权限边界

- 网络、数据库和 LLM 请求在适配器/工作器中，不进入纯策略内核。
- 事件只拼入技术候选之后的智能快照；不修改原状态机的模式、箱体、保护价格和技术触发条件。
- 贝叶斯和蒙特卡罗只输出结构化评估，不直接修改现金、持仓、pending、冷却或订单。
- 原版本与智能版本分别维护现金、持仓、冷却、待成交和日界状态。
- 模型训练离线、事件抽取异步；实时交易评估只读已经登记且可用的 artifact 与事件。
- 保护通道不等待贝叶斯、蒙特卡罗或 LLM，也不等待其他标的新仓批次完整。
- 两条通道不是两个交易写入者。唯一 writer 负责按已冻结顺序提交状态；模型工作器永不持有长时间账本写锁。
- 规则模式与贝叶斯状态后验分开命名；初期只有原状态机决定 `UP_TREND/RANGE/TRANSITION`。

### 3.3 保护通道优先级与数据不足行为

1. 优先处理可信退出事件、已有待退出指令、硬风险、旧日末根与新日基准。
2. 再处理取消入场、释放预留、过期评估。
3. 最后允许新仓评估结果提交和新增预留。
4. 同一逻辑时点的具体平局顺序由原执行规格在 M0/M1 冻结，不以模型返回快慢决定。

SOL 新仓数据缺失不能让已有 BTC 仓位的有效保护事件排队等待。涉及三币完整状态的新仓风险评估仍必须停止。

**保护通道继续运行，不等于没有报价也能成功退出。**没有可信可执行报价时保存 `EXIT_PENDING_NO_VALID_QUOTE` 和告警；保留原保护指令，不用旧报价、插值或未来报价伪造成交。恢复后按真实可用事件处理，不倒填过去价格。

只有 5m OHLC 的回放按已冻结 bar 执行代理处理；无法判断盘中时刻时保留代理属性，不能标为真实 quote 执行。

### 3.4 模式与隔离

| 运行模式 | 智能模型影响交易吗 | 要求 |
| --- | --- | --- |
| `BASELINE` | 否 | 原规则和原执行合同 |
| `SHADOW` | 否 | 旁路计算，不改变基线资金、延迟、机会或成交 |
| `HYBRID_CANDIDATE` | 仅影响独立虚拟账户的新仓准入/缩量 | 必须完成相应模型、合同和工程 Gate |

以上都是本期研究模式，不等同于现有项目的正式 EVAL/PAPER/SHADOW/实盘资格。新证据不得自动被旧执行消费者认作准入证明。

## 4. 版本、配置与实验身份

### 4.1 文档版本与策略版本分离

### 4.2 配置分层

| 配置 | 内容 |
| --- | --- |
| 基础策略政策 | 标的、A/B 参数、状态阈值、保护价格、期限、原成交优先级 |
| 智能政策 | 特征、贝叶斯、门槛、蒙特卡罗、模型失败和缺失处理 |
| 执行时间政策 | 快照时刻、评估预算、提交/最早成交、过期、quote/bar 代理 |
| 指标与验证政策 | 公式、单位、样本、成本、零分母、实验矩阵与验收 |
| 运行配置 | 数据路径、工作器、端口、提供商、限流、告警 |
| 凭据配置 | 仅环境变量或凭据管理，不进入仓库、报告、缓存或提示词 |

每个 run 绑定：基础政策、智能政策、执行政策、数学规格、指标规格、关键源码、数据 manifest、特征 schema、模型 artifact、提示词与缓存、成本、随机种子、依赖锁、执行类型及实验臂。

未知配置字段拒绝；未冻结必需字段为显式未决，不能当作默认通过。语义哈希覆盖所有影响决策的字段，不包含无关展示文字。

### 4.3 三类身份必须分开

| 字段 | 标识内容 | 不允许的用法 |
| --- | --- | --- |
| `economic_signal_id` | 一次原始技术机会：基础规则版本/政策、symbol、mode、signal_time、内核机会序号等 | 不因新闻到达、模型切换、快照重算而改变 |
| `evaluation_id` | 该机会的一次评估：特征/事件快照、模型、智能政策、组合快照、成本、时效 | 不能把每次评估当作新入场机会 |
| `entry_intent_id` | 该 run/实验臂对该机会批准的一次入场意图 | 不因重复投递或恢复而重复预留/成交 |

同一技术信号可有多个评估版本，但每个实验臂最多有一个活动入场意图；重评估必须记录 `supersedes_evaluation_id`。部分成交继续属于同一意图，累计数量不能超过批准数量。

不同实验臂可以研究同一个技术机会，数据库唯一约束必须包含 run/实验臂隔离，不能把基线成交误判成智能版重复，也不能在智能版内部重复开仓。

### 4.4 组合版本与过期结果

每次资金、持仓、预留、保护指令、冷却或风险基准变化都推进 `portfolio_version`。模型输入包含该版本及组合快照哈希。

最终提交采用版本比较：当前状态与评估状态不匹配时，旧结果不得用于入场。可按预登记次数在原信号失效前重评估；否则 `ABSTAIN_PORTFOLIO_CHANGED`。不能先预留资金，再无痕取消以迁就模型。

### 4.5 恢复与不可变性

不得用策略名称或“最新模型”恢复。恢复必须匹配原 run 的模型、源码/兼容合同、成本、提示词缓存、策略和配置。影响行为的版本不一致则拒绝恢复，创建新 run 或显式审批迁移。

模型数值与交易结果不就地覆盖；更正追加新记录、失效原因和引用。不得把失败运行覆盖为新的成功报告。

| `event_time` | 市场/新闻事件发生时间，可未知 |
| `published_at` | 来源声称的发布时间，不等于系统收到 |
| `received_at` | 本系统首次收到 |
| `available_at` | 完成必要处理后首次可以被决策使用 |
| `signal_time` | 对应原内核的 5m 收盘时间 |
| `feature_snapshot_frozen_at` | 本次智能评估输入冻结时间 |
| `evaluation_started_at` | 评估开始时间 |
| `evaluation_finished_at` | 模型及风险评估全部完成时间 |
| `decision_committed_at` | 最终决定在账本中提交的时间 |
| `earliest_fill_at` | 此决定允许开始寻找成交事件的最早时间 |
| `signal_expires_at` | 本次机会不再允许新增入场的时间 |
| `label_available_at` | 标签完整可知且完成处理的首次时间 |
| `model_training_cutoff` | 该模型允许访问的训练信息截止时间 |
| `model_available_at` | 训练、诊断、校准、登记完成后的时间 |

保留 `decision_time` 兼容字段时必须固定映射；V1.1 智能接口中它仅作 `decision_committed_at` 的别名，不同时表示信号时间或评估开始。旧接口语义不静默重写，采用版本适配器。

### 5.2 新仓批次不变量

```text
所有用于信号的 5m bar: bar.start + 300 <= signal_time
刚闭合的 1H 输入: hourly.start + 3600 == signal_time
非整点不伪造新的完整 1H

feature.available_at <= feature_snapshot_frozen_at
feature_snapshot_frozen_at <= evaluation_started_at
model_available_at <= evaluation_started_at
training_label.label_available_at <= model_training_cutoff

evaluation_started_at <= evaluation_finished_at
    <= decision_committed_at <= earliest_fill_at

有效新成交必须发生于 earliest_fill_at 之后，且不晚于 signal_expires_at
```

规则信号只使用原合同允许的闭合市场信息；信号后、快照前已收到的事件可以进入智能快照，但不能倒写技术信号。快照冻结后新到事件不能插入正在运行的评估。

LLM 事件：`available_at = max(首次收到时间, 推理完成时间, 校验完成时间)`。模型 artifact 可用时间不能早于实际/显式模拟的训练和登记完成时间。

新仓批次先校验三币同一闭合时间、完整性、重复与顺序，再产生候选。未来数据、冲突重复、倒序和不对齐输入原子拒绝新仓批次，禁止局部消费后假装整体成功。

**这条原子性不覆盖独立保护队列。**合法的已有持仓保护事件可以先提交；不完整的新仓批次不能阻塞它，也不能因此伪造缺失标的状态。原基线回放的批次语义仍由兼容测试保证不变。

### 5.3 延迟、下一开盘与成交合同

冻结两种明确不同的研究执行模式：

| 模式 | 成交规则 | 报告标签 |
| --- | --- | --- |
| 旧版兼容回放 | 原技术基线的下一开盘及原冲突顺序 | `LEGACY_BAR_PROXY` |
| 智能时延感知 | 决定提交后，才允许使用后续合格报价；缺少逐笔报价时按预登记后续开盘代理 | `QUOTE_AWARE` 或 `DELAYED_BAR_PROXY` |

假设 10:00 K 线闭合，10:00:01 收到数据，10:00:03 评估完成，则智能版本不能在 10:00:00 的开盘价成交。

- `earliest_fill_at` 包含最终提交和冻结执行延迟，不是信号时间的别名。
- 报价必须满足时间、来源、价差、freshness 和数量合同；迟到的过去报价不能成为当时已可成交的证据。
- 只有 OHLC 时，不插值 10:00:03 的成交价。M1 默认研究方案为等待后续不早于允许时刻的 bar open；若已过期则取消。M0/M1 必须验证它与原保护规则兼容并冻结代理标记。
- 不先读取下一根涨跌结果，再决定接受/拒绝或采用哪种延迟。
- 入场前重新执行原价格越界、现金、硬风控和信号失效检查；不重新拟合模型以接受更差价格。
- 历史重放使用显式逻辑时钟、固定或预登记分布的延迟。执行机器偶然快慢不能随机改写历史成交。
- 前向运行记录实际延迟；数值评估完成得再晚，也不能回填过去成交。

基线兼容与延迟对照分开：`BASELINE/SHADOW` 不受旁路耗时影响；另建匹配时间政策的 `T_latency` 对照，用于隔离延迟效应。

### 5.4 数据质量与失败处理

- 保留 250 根连续完整 1H、100 根完整 5m 预热；真实缺口后按原规则重新预热。
- 每根 1H 由完整 12 根 5m 证明；量能特征启用后核对成交量。
- 历史 candle-close 可用性明确为研究假设；实际接收证据另列。
- 新闻更正、撤回、冲突追加版本，不覆盖历史可见内容。
- 没有历史可用时间证据的新闻不进入严格时点回测。
- 新闻未出现、源断流、LLM 失败、事件已过期分别编码，不统称中性。
- 当前交易所过滤规则用于历史回放时继续标记代理，不宣称历史规则已恢复。
- 无效输入进入隔离记录，不允许负价格、NaN、无穷大、未来时间、冲突重复静默进入特征。
- 缺少组合任一相关持仓的可信输入时停止新仓风险准入；已有各币保护通道按自身有效事件继续，组合估值不能显示为完整可靠。

### 5.5 LLM 历史知识污染

今日模型可能已知历史事件后果。仅输入旧新闻不能证明无未来知识。

历史 LLM 输出只作开发实验；限制引用输入证据，不自由补充后果。真正验证 LLM 增益依靠提示词、参数和特征政策冻结后的新发生前向事件。历史缓存固定输出不等于历史无泄漏。

## 6. 数学规格

所有新增数值为研究设计，不宣称已验证盈利。实现前冻结数学、指标、时序和执行政策；公式必须映射到具体函数、测试与报告字段。

### 6.1 技术分析保持原定义

```text
EMA_n(t) = alpha*C_t + (1-alpha)*EMA_n(t-1), alpha=2/(n+1)
EMA 首 n 根以简单均值初始化。

TR_t = max(H_t-L_t, |H_t-C_(t-1)|, |L_t-C_(t-1)|)
ATR_14(t) = [13*ATR_14(t-1)+TR_t]/14
首 14 个 TR 取均值；第一根 TR 使用 H-L。

ER_24(t) = |C_t-C_(t-24)| / sum(i=t-23..t, |C_i-C_(i-1)|)
分母为零时 ER=0。
slope_t = EMA_50(t)-EMA_50(t-3)
```

趋势突破、六根止损窗口、冻结箱体、两小时确认、模式失效和保护顺序沿用原规格。不得同时重写技术规则与智能筛选，否则无法独立归因。

### 6.2 成本、标签与 R 单位

以信号参考价 C、止损 S、目标 T、每边手续费 f、执行代理 s 定义：

```text
E = C*(1+s)
X_stop = S*(1-s)
X_target = T*(1-s)
L_net = E-X_stop+f*(E+X_stop)
G_net = X_target-E-f*(E+X_target)
expected_net_rr = G_net/L_net
R_net = 实现净盈亏 / (实际执行数量 * 信号时冻结的 BASE L_net)
```

`L_net<=0`、非有限数或量纲不一致直接拒绝，不返回伪造 R。压力风险预算用压力预计损失；BASE R 分母不随实际亏损、压力或模型后验扩大。

#### 6.2.1 报价与成本不双扣

- 有真实 bid/ask 时，价差通过买入 ask/卖出 bid 体现；额外滑点仅表示报价之外的执行损耗。
- 仅有 OHLC 时，使用冻结的执行代理并记录 `execution_quality=proxy`。
- 信号参考成本、预计风控损失和实际成交净盈亏分别存储。
- 数量取整、最小金额和固定费用可能使单位结果随数量变化；不能默认按数量严格线性放大。

#### 6.2.2 标签来源与可比性

标签通过共享成交/保护规则生成，包括止损、止盈、超时、模式失效、缺口和执行失败。目标先触及、净收益为正、条件均值为正是三个不同问题。

保留全部原始规则候选，包括被组合额度或模型拒绝的候选。每条记录包含技术机会、所处 run/实验臂、原拒绝原因以及标签来源。

被拒绝候选可生成独立假设单笔结果，必须为 `counterfactual_label`。不能计入实际虚拟成交数、组合收益或收益验收样本。

训练数据必须预先固定标签总体和执行定义：

- 采用规则候选标准化标签时，固定参考数量/费用口径和执行政策；不因哪个数量回测好而选参考数量。
- 若只使用实际执行样本，明确存在的选择与仓位条件，不能宣称覆盖全部规则候选。
- 同一技术机会的真实与反事实结果不作为两笔独立训练样本重复计数。
- 训练目标、线上输入和回放必须对应同一执行时序；不能用零延迟结果训练、再冒充真实时延下的净 R 预测。
- 模型拒绝会改变后续现金与冷却；不同实验臂因此出现的机会集差异必须记录，不能虚构完全相同的可交易总体。

`R_net` 的实际账本指标与模型标准化目标允许分开命名，但不能混用。M1 冻结 `label_execution_policy_id`、`reference_quantity_policy_id` 和 `label_source_policy`。

#### 6.2.3 删失与末端清算

- 完整到达原策略退出条件的标签可标 `MATURED`。
- 数据结束、缺口或运行提前停止导致未观察完整结果，标 `CENSORED/UNAVAILABLE`，不填零收益或默认亏损。
- 为组合报表按原合同进行末端清算时，记录 `END_OF_RUN_LIQUIDATION`、价格依据和成本；它不自动成为正常持仓期限的训练标签。
- 未退出仓位的 mark-to-market、真实虚拟实现收益和研究终止清算单独列示。
- 原回放如果强制末端清算，保留其账本行为；统一比较时使用相同终点政策，不把它解释成策略主动退出。

重叠信号、同日多币并非独立样本。保存 `dependency_group_id`、标签信息区间和日历日期；统计按同步日期区块处理。

### 6.3 贝叶斯：简单分层先行，动态模型后置

#### 6.3.1 第一版主研究模型

采用有拟合和诊断的简单分层 Student-t 净 R 回归，而非固定状态后验到胜率的权重映射：

```text
R_j ~ StudentT(nu, mu_j, sigma_mode)
mu_j = alpha_mode + u_symbol,mode + beta_mode^T*x_j
u_symbol,mode ~ Normal(0, tau_mode^2)
nu > 2
```

此处层级效应记为 `u_symbol,mode`，自由度记为 `nu`，实现 schema 中禁止同名混淆。最初不加入日期动态隐状态。

x 只使用当时可知、训练段拟合变换的特征。技术特征上限保留 8 个：例如 ER、ATR/价格、归一化斜率、突破距离、箱体位置、量能变化、BTC/ETH 相对收益。模式不适用字段保存缺失掩码；LLM 特征为后续预登记扩展，不与首轮同时调参。

建议先验方向保持原版：标准化特征系数为以零为中心的收缩先验，组均值以零净优势为中心，尺度参数取正分布。具体先验与缩放尺度通过先验预测检查在 M1 冻结，不读取最终评估收益调整。

简单分层不代表候选之间已经独立。M1 必须冻结重叠机会去重/训练取样和剩余依赖性检查；需要时将非动态组效应作为单独登记的模型修订。同步日期区块报告不会自动修正错误的独立似然后验；若相关候选导致可信区间明显过窄，维持旁路，不启用 `p_edge/q05_mu` 准入。采样链 ESS 是推断数值诊断，不是有效独立市场交易数。

#### 6.3.2 Student-t 的角色及适配检查

Student-t 是候选收益回归起点，不自动成为完整真实交易收益分布。它无界，而固定数量、成本和资金约束下的现货多头收益存在经济支持边界；退出规则也可能造成非对称、多峰或局部集中。

因此必须：

1. 根据标签合同推导可行损失范围，并统计模型在不可能区域分配的概率质量。
2. 检查止损附近、目标附近、超时样本、极端亏损、不同模式/币种的预测匹配。
3. 区分 `mean_inference_valid`、`predictive_probability_valid`、`predictive_tail_valid`。不能以均值拟合尚可替代全部分布通过。
4. 若支持域或尾部错配达到冻结失败条件，输出 `MODEL_MISSPECIFIED/ABSTAIN`；停止宣称完整获利概率或尾部风险有效。
5. 不对输出事后截断或裁尾后宣称校准通过。需要受限支持模型、退出类型混合模型时，作为新版本研究，重新验证。

此模型不负责代替蒙特卡罗的组合路径风险；后验单笔 R 不能直接加到市场收益上。

#### 6.3.3 日期动态状态：挑战模型，不是 V1 准入必需品

只有简单模型完成旁路验证后，才比较：

```text
mu_j = alpha_mode + u_symbol,mode + beta_mode^T*x_j + eta_day(j)
eta_day = phi*eta_previous_calendar_day + epsilon_day
epsilon_day ~ Normal(0, omega^2), |phi|<1
```

新增模型必须定义连续 UTC 日历，包括没有候选的日期；跨多日不能只推进一个“交易样本步”。预测未来隐状态不得使用未来结果或全时段平滑后验。

V1 run 内参数和状态基准冻结，只允许从登记时已有状态按时间向前预测，不用该 run 后续标签偷偷更新状态。若要在线过滤/更新，另设版本、可用时间和验证合同，不把它称为“没重新训练所以不算变更”。

动态模型需报告相对简单模型的时间外增益、敏感性及计算成本；复杂度本身不构成升级依据。

#### 6.3.4 输出定义

```text
p_win(x) = P(R_new > 0 | x, D)
mu_pred(x) = E[R_new | x, D]
p_edge(x) = P(E[R_new | x, theta] > 0 | D)
q05_mu(x) = 各后验参数下条件均值的 5% 分位数
predictive_quantiles = 新交易净 R 后验预测分布的分位数
```

`q05_mu` 不是交易净 R 的第 5 百分位；`p_edge` 不是下一笔获利概率。后验可信程度不等于频率学错误率，也不等于未来策略可靠性。

每次输出同时保存模型/标签/特征版本、训练截止、有效样本与分组覆盖、推断诊断、输入越界、缺失和计算误差状态。无效概率为 null 加原因，不以 0.5 或绿色通过替代。

#### 6.3.5 诊断与验证分开

| 对象 | 验证方法 |
| --- | --- |
| `p_win` | 对后续净收益正负做 Brier、对数损失、可靠性图与分组校准 |
| 净 R 分布 | 预测检查、区间覆盖、分布评分、收益误差、支持域和尾部检查 |
| `p_edge/q05_mu` | 推断诊断、先验敏感性、合成参数校验及后续决策结果；不对单笔输赢做“优势胜率校准” |
| 推断算法 | 解析小例、模拟校准、收敛、ESS、发散等；不代替真实市场验证 |

M1 冻结 `rhat_max`、`bulk_ess_min`、`tail_ess_min`、`divergences_max`、其他采样异常阈值、支持域错配容忍度和样本/覆盖要求。缺少这些字段不能升级模型。

使用成熟概率编程工具，在隔离环境验证依赖。正则化点估计不冒充后验；训练命令成功返回也不等于模型诊断通过。原资料参考的 Stan 后验预测说明保留在 §15 来源中。

### 6.4 贝叶斯准入

先旁路记录所有预测。达到冻结模型验证条件后，独立智能政策才可启用 `q05_mu > 0` 筛选；连续均值后验下与约 95% 正均值可信程度相关，不作为两份独立确认。

95% 仍是待 M1 预登记的研究门槛，不是经优化确认的最优值，不改变 A/B 技术规则。

下列任一成立必须 `ABSTAIN`：缺样本/分组覆盖、推断失败、模型过期、输入越界、特征或标签版本不匹配、目标分布明显错配、模型评估过期。

若只验证了均值推断但未验证尾部，不显示可靠尾部分位数；是否允许均值型候选研究，由 M1 明确冻结，不能运行时临时放行。`ABSTAIN` 仅限制新开仓，不阻断保护退出。

### 6.5 蒙特卡罗：同步路径、真实风险基准和数值误差

#### 6.5.1 三类模拟不混用

| 模拟 | 输入与方法 | 允许解释的结论 |
| --- | --- | --- |
| 研究不确定性 | 同步日期区块重采样真实交易/组合记录 | 历史指标不确定性，不是新增交易证据 |
| 候选组合风险 | 同步多币 5m 市场路径，已有持仓、pending 和拟新增仓位 | 有限期限、给定假设下的路径风险 |
| 人工压力场景 | 跳空、滑点扩大、相关性上升、报价中断等预登记情景 | 脆弱性，不附未经估计的发生概率 |

人工压力结果必须保留 `scenario_type=stress`，不得混入概率平均值形成伪精确风险。若压力结果被用于否决，必须预先定义该压力准入政策。

#### 6.5.2 历史同步抽样与当前状态

V1 基础模型使用只含过去数据的同步 BTC/ETH/SOL 区块抽样，不能分别打乱，也不能先删除非目标行情再拼接不相邻片段。

必须记录 `history_start/end`、可用区块、区块长度、跨币缺失、抽样权重与种子。仅保留满足预登记连续性要求的合法区块；被剔除区块和缺口必须审计。

**保留历史相关性不等于已完成当前市场条件化。**V1 分开输出：

- `historical_bootstrap_risk`：冻结历史窗口的基础风险估计。
- `current_state_sensitivity`：近期窗口、波动水平、相关性或流动性变化下的敏感性。
- `stress_risk`：不附真实概率的人工压力。

M1 指定哪些历史窗口/当前状态条件可以用于正式候选风险 Gate。未验证的波动缩放、相关性上调不能被称为已经校准的当前风险分布。证据不足时保持旁路，或依据明确的保守研究政策弃权，不悄悄挑风险最低窗口。

#### 6.5.3 市场路径重建

抽样单位包含整段 OHLC 相对变化：开盘相对上一收盘、high/open、low/open、close/open，保持三币同步区块。重建后验证：

```text
价格有限且 > 0
high >= max(open, close)
low <= min(open, close)
low <= high
时间递增，三币同步，边界跳空有记录
```

禁止从 close 插值虚构 high/low；非法路径拒绝并计数，不无痕修正成合法样本。区块拼接处的跳空和依赖损失必须说明。

未来模拟使用未来日历时间推进持仓与日界，不把被抽中的历史新闻、已知未来事件或历史绝对时间直接搬到模拟路径。历史量能/报价特征仅在已定义联合抽样方式下使用。

#### 6.5.4 可执行报价与盘中顺序

- 历史含同步 bid/ask 时，记录来源、新鲜度、价差、额外滑点、报价大小可用性和市场路径对应关系。
- 只有 OHLC 时，价差/滑点属于执行代理，输出 `execution_quality=proxy`。不得称为真实可执行 Bid 分布。
- 有 quote 但顺序、时间或 size 不完整时，不能假定任意数量均按该报价成交；遵守原执行代理及明确限制。
- 同一 bar 同时触及止损/止盈，延续原保守顺序；不把未知顺序解释成模型准确预测。
- 三币同一 bar 的 low/high 未必同时发生。组合主风险统计需声明是“闭合时点权益”还是“有序报价路径权益”；仅有 OHLC 的盘中最不利拼接作为保守界限/敏感性单列。
- 未知盘中顺序造成的区间不确定性，不能仅增加路径数就宣称消除。依赖精确盘中风险概率的准入，在无相应数据证据时不得标为已验证。

训练标签、真实候选模拟与风险路径调用同一保护/成交语义。共享纯函数需原所有者先补兼容回归再抽取，不另写第三套止损实现。

#### 6.5.5 组合风险快照

新增 `PortfolioRiskSnapshot` 至少保存：

```text
portfolio_version, portfolio_snapshot_hash, as_of
cash, reserved_cash, available_cash
positions, pending_entry_intents, pending_exit_intents
protective_prices, remaining_holding_time
current_liquidation_equity
mark_quality_by_symbol
risk_day_id, day_start_equity, day_baseline_status
historical_high_watermark
remaining_daily_loss_budget
remaining_position_risk_budget
loss_streak, cooldown_until
cost_policy_id, execution_policy_id
```

风险评估从当前真实虚拟组合出发，包含已批准未成交计划及拟新增方案。不得把资金预留同时算成现金损失和新仓支出。当前资金恒等式、预留和实际扣款必须分别定义。

模型只评估现有及拟加入风险，不假设未来再产生新信号/新闻，不递归调用贝叶斯或蒙特卡罗。若已有组合风险超限，m=0 也不是“通过新仓”；拒绝新开仓并按原硬风险政策处理已有仓位。

#### 6.5.6 风险公式与日界

V 为可退出标记权益，价格和费用类型必须随结果记录：

```text
V_t = cash_t + sum_s(q_s,t * 可退出标记价格_s,t - 预计退出费用_s,t)
V_now = 当前可退出权益
V_day = 当前风险日已冻结的日初权益
H_now = 该运行定义下已确认的历史权益高水位

MDD_incremental,h = max(t<=h, 1 - V_t/max(V_now, max(u<=t, V_u)))
MDD_from_hwm,h = max(t<=h, 1 - V_t/max(H_now, max(u<=t, V_u)))
Loss_terminal,h = (V_now - V_h)/V_now

L_day_abs = V_day * (1 - daily_loss_limit)
remaining_daily_loss_budget = max(0, V_now - L_day_abs)
```

`remaining_daily_loss_budget` 表示到日亏损线的权益距离，不等于可开仓预计风险预算；二者分别约束。预留已在资金/预计风险账本中体现时，不重复扣。

日内亏损概率为路径触及当前有效日亏损线的比例，不是每次把当前权益当新日初。累计回撤线按已冻结高水位和原规定计算。

跨 UTC 日界继续沿用原规则：23:55 最后一根闭合先判断旧日损失，旧待退出不清空；新日基准由新日实际有效开盘建立。在模拟路径中使用对应的未来模拟新开盘，而不是继续用旧 V_day 或把风险预算无条件重置。

新日基准因缺失报价尚未建立时，记录 `DAY_BASELINE_PENDING`，不允许为新仓假造完整日风险预算。保护退出仍保留。

示例（仅说明公式）：日初 10,000、当前 9,910、日亏损上限 1%，距离风险线只剩 10；不能从当前权益重新获得 1% 亏损空间。

每个结果分别报告：

```text
p_incremental_mdd_breach
p_daily_loss_breach
p_hwm_drawdown_breach
risk_line_definitions
valuation_basis
```

不得都显示为一个模糊“回撤概率”。

#### 6.5.7 期限、VaR 与 ES

初始研究期限继续为未来 6 小时，必须在 M0/M1 核实覆盖当前最长剩余持仓；3h/6h 与模式映射以原规格为准。1 日、7 日只作扩展，注明“无后续新开仓”等假设。

```text
P_breach = 触及指定风险线的模拟路径数 / N
VaR_alpha = Loss_terminal,h 的 alpha 分位数
ES_alpha = Loss_terminal,h 最差 (1-alpha) 概率质量的平均损失
```

ES 的排序、边界分数权重与分位数方法在数学规格冻结。例如尾部样本质量为 `m=N*(1-alpha)`，最差 `floor(m)` 条取完整权重，下一条取剩余小数权重，再除以 m。不得不同报告各自采用不同插值。

保留研究展示 `P(MDD_6h>1%)`、ES95 和回撤分位数，但必须明确这里的 MDD 基准与盘中数据依据。原建议 `P(MDD_6h>1%)<=5%` 仍是待预登记研究阈值，不自动成为新批准限制。

#### 6.5.8 数值误差与临界准入

离线默认起点保留 5,000 条路径。实际路径数、历史窗口、区块长度、延迟上限和停止条件经 M1 数值测试冻结。

风险概率输出 `k/N` 之外，还必须输出单侧蒙特卡罗数值误差上界。只有该上界满足已冻结限制，才可声称在给定模拟模型下通过数值 Gate；不能用 4.9% 的点估计直接证明低于 5%。

一种可实现的研究合同为：独立模拟路径指示量的单侧精确二项上界，按冻结数值置信水平计算；k=N 时上界为 1，k=0 时上界仍大于 0。采用其他方法必须登记方法及覆盖测试，不得显示没有定义的“±误差”。

- 上界只控制计算随机性，不控制历史短、模型错配、市场变化或概率校准误差。
- 多仓位档位/多次数值加样的比较，预先分配误差预算与最大次数，不能不断重抽直到通过。
- 不同数量使用共同随机路径，减少随机噪声对缩量选择的影响；路径样本量不当作真实市场样本量。
- 固定种子复现、不同种子敏感性和 N/区块长度敏感性分别报告。
- 逼近门槛而预算内无法判定时，`ABSTAIN_MC_PRECISION` 或选已证明通过的更小数量，不延误保护通道。

若模拟路径指示量并非独立抽样，不得直接套用独立二项误差公式；更换误差合同或明确不能用于该数值 Gate。

#### 6.5.9 不伪称统一贝叶斯生成模型

本版贝叶斯估计信号优势，蒙特卡罗独立评估市场路径风险。接口相接，不宣称已形成联合后验预测。后续完整参数不确定性传播需单独建模验证，不能把净 R 后验与价格收益重复叠加。

### 6.6 仓位与最终决策

```text
q_base = min(
    单笔风险预算/当前成本场景的单位预计止损损失,
    剩余组合风险预算/单位预计止损损失,
    标的剩余名义上限/预计单位买入支出,
    未预留可用现金/预计单位买入支出
)
q_candidate(m) = 向下适配交易所步长(q_base * m)
m 属于预登记的 {0, 0.25, 0.5, 1}
```

只允许拒绝或缩量，不超过原预算；步长取整后重新核对最小数量、最小金额、费用、现金和全部 Gate。小于最小额则不交易，不向上取整凑单。

不同数量风险不假定严格单调；评估冻结网格，用同一组路径。选择规则预先定义，例如选择全部条件通过的最大档位，不根据后续收益挑档位。m=0 表示不新增仓位，不记录为零数量成交。

三币同一信号时间的竞争保留 BTC、ETH、SOL 顺序。顺序涉及评估版本、资金预留和最晚提交；不得让最快完成的模型抢走预算。保护事件可打断新仓提交，并使旧风险结果失效。

新仓顺序：数据合格 → 原技术信号合格 → 快照冻结 → 贝叶斯可用且通过 → 离散风险方案通过 → 时效与组合版本一致 → 原独立硬风控和现金通过 → 原子创建意图/预留 → 后续有效成交事件再次检查。

原硬风险继续保留：单笔 0.25%、组合预计风险 0.50%、最多两仓、单币名义 25%、日亏损 1%、连续三亏暂停两小时。原预算分母、亏损统计和暂停计算在 M0 核验；不因本文简写而改规则。跳空实际超限如实记录。

新仓 `ACCEPT` 不是成交。实际成交前变为超时、越界、风险关闭或配置不匹配，必须显式取消，释放预留并记原因；不改止损/目标使它重新满足条件。

## 7. LLM 接入设计

### 7.1 两个权限明确的用途

1. 事件提取：输入允许来源文档，输出资产、事件类型、时间、原文证据、冲突与缺失。
2. 解释生成：基于已冻结数值决定生成中文说明；失败不改变入场、退出或资金状态。

初期仅有限类型：公告、网络运行事件、交易服务异常、已发布重大宏观事件等。新来源/类型登记。没有授权来源则 `SOURCE_UNAVAILABLE`，不靠模型编造新闻。

### 7.2 结构化输出合同

```text
extraction_id, schema_version, source_id, source_document_id, document_hash
canonical_event_id, source_occurrence_id, event_version
published_at, received_at, extraction_finished_at, validated_at, available_at
symbols, event_type, factual_claims, evidence_spans
conflicts, uncertainty_reasons, expires_at, retracted_at
provider, model_id, prompt_hash, output_hash, status
```

禁止有执行权限的 buy/sell、数量、止损、收益保证或配置变更。`factual_claims` 必须定位到原文证据；模型自报置信度不转成交易成功概率。

### 7.3 文档去重与事件去重分离

- `document_hash` 识别完全相同内容，不能自动识别不同网站转载同一事件。
- `canonical_event_id` 标识同一经济/业务事件，关联多个 `source_occurrence_id`。
- 同一事件多来源报道保留来源证据，但默认只贡献一次事件计数，不能把转载次数当独立利好。
- 聚类规则、时间窗和冲突处理在 M1/M6 冻结，必要时人工核对；不能因为模型说“同一事件”就无证据合并。
- 去重、合并、更正都追加有可用时间的版本。后来才识别为重复，不能回写历史快照使它看起来当时已经知道。

### 7.4 时延、失败和缓存

- 内容、模型、提示词、schema 共同决定缓存键；保存经脱敏的原响应、校验和版本。
- 温度为零不保证远端逐次一致。历史复现读取冻结输出，不重新请求。
- LLM 不在每根 5m 临时阻塞调用；事件完成后才更新可用仓库。
- 超时、限流、额度耗尽或校验失败不追补过去交易。
- `NO_EVENT`、`SOURCE_DOWN`、`LLM_FAILED`、`VALIDATION_FAILED`、`EVENT_EXPIRED` 分开。
- 无 LLM 实验继续自身固定政策；启用强制事件特征的实验遇到源故障，按政策停止新仓，不静默退回另一策略。
- 解释性 LLM 失败不影响任何已经冻结的数学决定。

### 7.5 安全与成本

外部文档和模型输出都是不可信数据。工作器不持有 shell、交易密钥、交易 API、原执行证据表写权限或任意网络权限。文档提取输出先进入 staging，经可信校验组件接纳；工作器不能直接修改交易账本。

原资料引用的 OWASP 提示注入防护作为补充阅读，权限隔离与输出校验才是执行边界，不仅靠提示词。

先实现 fixture 适配器；真实提供商、精确模型标识、来源授权、凭据、每日/单任务费用上限由用户确认后启用。默认不购买订阅、不切换计费供应商、不多模型并行耗费。

如果使用代理/转发服务，M6 必须登记端点归属、模型身份验证能力、数据保留与出境政策；未确认不能将服务商显示名称当作已经核实的官方模型能力。

### 7.6 启用顺序

LLM 来源采集、人工标注和 fixture 开发可以提前并行。**真实事件特征参与筛选晚于 T+B+M 数学闭环**，不阻塞无 LLM 的工程验收。

先验证资产/类型识别、时间抽取、证据支持率、跨来源去重、弃权、攻击样本和每事件成本。通顺解释不替代准确；抽取准确不等于交易收益增益，后者通过冻结后的新前向样本另证。

```python
commit_entry_intent(adjustment, expected_portfolio_version) -> CommitResult
process_protection_event(validated_event, ledger_state) -> ProtectionTransition
```

接口名称不意味着当前仓库已具备函数。具体签名经 M1 schema 冻结，不引入不必要网络调用。

`DecisionAdjustment` 只允许 `ACCEPT/REJECT/ABSTAIN`、不大于 1 的数量比例、选定数量方案 ID、原因、证据、版本、时间与有效期。不得包含新止损/目标。

`ACCEPT` 只是建议，writer 提交后才有活动意图；`REJECT/ABSTAIN` 不预留现金。工作器不能直接调用成交 API。

### 8.2 提交事务

提交时必须在短事务内复核：

```text
run/模式允许候选准入
signal 未失效、未消费、未已有活动 entry_intent
model/feature/policy/cost/execution 版本匹配
评估对应 portfolio_version 与当前一致
风险 forecast 的数量/成本/时间/状态仍对应本次方案
独立现金、持仓、日风险、冷却和原价格条件通过
```

事务写入决定、意图、现金/风险预留、已消费身份、审计和 checkpoint。失败则全回滚；不能产生“决定未保存但资金已减少”或“重放后再成交一次”。

在最终成交事件发生时，再次执行原入场越界、失效与硬风险检查；变更数量须符合冻结政策、原子更新和可追溯，不无痕替换评估。

### 8.3 插件兼容与状态更新

无插件与 SHADOW 必须逐 bar 重现原修正后基线决策、交易、数量和权益；智能工作器不可以让纯内核漏掉已有持仓期间的状态更新。

智能时延版与零延迟旧版允许按执行政策产生差异，但所有差异要分类为模型、风险缩量、时延/报价、资金路径或数据问题，不能用“架构不同”掩盖回归。

## 9. 训练与防泄漏验证

### 9.1 时序与曝光

1. 先登记历史曝光日历；已暴露历史只做开发与描述性评估。
2. 训练、开发/校准、评估分区按日历向前推进，不随机打乱。
3. 以标签真实信息区间清除跨边界重叠；6h 最长标签至少覆盖相应隔离，并纳入处理/执行延迟。
4. 标准化、缺失处理、特征选择、先验/门槛选择、校准都只访问各自允许的数据段。
5. 同一时点跨币一起分区；不能训练 BTC 当天结果再验证同一天高度相关 ETH 结果。
6. 所有政策、模型、特征、提示词、MC 方案都算实验，写入账本和预算。
7. 模型训练、检查和登记完成后才服务后续时点。历史拟合不能零延迟“回到过去”。
8. AR(1) 或状态模型的训练、过滤和预测窗口分别审计，不使用未来平滑状态。
9. 评估完整组合并按币种、模式、日期、事件分层；重叠反事实记录不当作独立成交。
10. 通用时间序列拆分器不替代标签 purge、隔离、曝光审计及权限限制。

### 9.2 最少实验矩阵

在已冻结 A/B 政策中按原流程选定基础政策；两者都失败时只能标“研发参考”，不宣称赢家。

| 实验 | 作用 | 要求 |
| --- | --- | --- |
| T | 原技术策略基准 | 保持原行为和原执行政策 |
| T_latency | 仅匹配智能链路的时延/报价政策 | 不增加模型筛选；隔离延迟效应 |
| T+B | 仅贝叶斯筛选 | 与可比基准用一致执行、费用与预算 |
| T+M | 仅蒙特卡罗拒绝/缩量 | 明确不是单纯提高胜率 |
| T+B+M | 数学闭环主实验 | 本期首个集成目标 |
| T+B+M+L | 增加事件信息 | 提示词和参数冻结后评估真实新前向样本 |
| T_exposure_control | 预登记的固定或简单确定性缩量对照 | 缩量系数仅用训练/开发段确定，评估期冻结 |
| Cash | 不新增交易的现金参照 | 不能以零回撤宣称智能模型成功 |

`T_exposure_control` 用于识别收益/回撤改善是否主要来自降低暴露，不追求事后精确匹配智能版的已实现暴露；后者会引入未来信息。可以事后展示描述性暴露归一化，但不能冒充预注册策略结果。

实验数量和预算在 M1 固定。表中各臂用于贡献归因，不是授权从大量组合中选择最高收益；任何新增组合都登记新实验。暴露、候选数、接受率、持有时间、换手、延迟和费用一起报告。

### 9.3 三类成本报告

每个可评估版本分别输出：

1. **BASE：**基准成本下的完整组合。
2. **固定交易双倍成本：**在原已执行交易集合上重算费用/滑点，明确哪些成本翻倍、不改交易序列。
3. **完整压力回放：**在压力成本下重新执行数量、预算、拒绝和现金路径，交易序列可改变。

三类不能混为一个压力 PF。双倍成本是金额还是费率倍增、价差如何处理，M1 从原合同核对冻结，不能双扣 bid/ask 价差。

### 9.4 贡献解释边界

报告分别说明：筛选效应、仓位/暴露效应、时延/执行效应、事件信息效应。比较依赖具体实验政策和机会集，不把简单收益差写成已证明的因果贡献。

若模型与基线无显著或稳定改善，报告没有新增证据。不得转而增加模型复杂度、放宽风险上限或挑历史窗口来获得成功。

### 10.3 指标合同：不能只有名字

新增 `HYBRID_METRIC_SPEC_V1_1.md`。每个指标必须有：标识、公式、单位、样本总体、时间范围、成本政策、价格依据、初始资本/风险分母、零分母处理、未结/终止处理、阈值与来源、版本。

基础描述性指标可同时保留以下定义，不自动代替原门槛使用的口径：

```text
对已完成、实际执行的虚拟交易 i：
pnl_i = 扣除规定交易成本后的净盈亏
r_i = pnl_i / (实际数量_i * 信号时冻结的 BASE L_net_i)

PF_pnl = sum(max(pnl_i, 0)) / abs(sum(min(pnl_i, 0)))
PF_R   = sum(max(r_i, 0))   / abs(sum(min(r_i, 0)))
Payoff_pnl = mean(pnl_i | pnl_i>0) / abs(mean(pnl_i | pnl_i<0))
Payoff_R   = mean(r_i | r_i>0) / abs(mean(r_i | r_i<0))
Mean_net_R = mean(r_i)
Cumulative_trade_R = sum(r_i)
Portfolio_MDD = max_t(1 - V_t/max_u<=t(V_u))
```

`PF_pnl` 与 `PF_R` 在缩量后可能不同，必须分别命名；`Cumulative_trade_R` 不是组合收益率，也不自动等于原 `10R`。

零净盈亏交易单列 breakeven；不在盈利或亏损条件均值中，但纳入整体平均净 R 和实际交易数。无亏损时 PF/Payoff 不能用 999 等伪造大数；输出 null/明确状态及全部计数，不能因此自动通过充分证据验收。

同一意图部分成交的收益归并、分批退出和终止清算计数规则从原合同核对冻结，不能拆单凑样本。手续费币种换算若需要，只用当时可用规则并记录。

LLM、计算、数据采购成本与交易手续费分账。交易研究门槛使用原冻结合同；另报研发/运行费用，不把忽略运行成本后的成绩称为个人已实现净利润。

### 10.4 原收益与风险门槛保留

除非单独明确审批，**不降低原 V1.0 的研究要求**：

| 要求 | 保留阈值 | V1.1 必须核实的定义 |
| --- | --- | --- |
| 组合净 payoff | >=1.8 | 金额还是 R 的条件均值比率 |
| BASE PF | >=1.30 | 使用金额/R 哪一口径，与原基准一致 |
| 平均净 R | >0 | BASE 风险分母、实际完成交易范围 |
| 固定交易双倍成本 PF | >=1.05 | 哪些成本翻倍，固定交易与数量 |
| 完整压力回放净期望 | >0 | 压力参数、重跑资金路径及指标单位 |
| 组合最大回撤 | <=5% | 估值频率、可退出价格、初始基准与终点 |
| 原适用 `10R` | 原定义、原方向、原阈值不变 | 原材料未给完整定义，M0/M1 必须取证 |

不得自行把 `10R` 改写为累计盈利、止损额度或最大回撤。来源未定位前可做研发测试，但不能宣称完整收益验收通过。

两模式分别报告原门槛。真正独立评估中的实际虚拟交易合计至少 200、每模式至少 50、拟声称有效的 symbol×mode 至少 30。这里是原必要下限，不是充分统计证明；已暴露历史和反事实重叠标签不能凑独立样本。

保留同步日期区块下平均净 R 区间，以及去掉最佳标的/最大赢家的敏感性。蒙特卡罗 5,000 路径不是 5,000 笔真实交易。

### 10.5 模型与风险 Gate

- 概率不只看 AUC；对适当事件检查 Brier、对数损失、校准图、覆盖、分组和样本量。
- 参数后验诊断、交易预测校准、蒙特卡罗计算误差、市场风险校准分别报告。
- MC 某风险事件过少时，不能用零观察证明模型已准确校准尾部概率。
- 实际损失与预测风险对照使用同一期限、同一风险线、同一已有/待成交/拟新增计划定义。
- 模型失败、未决合同或独立样本不足时，按阶段交付“不通过/不足”，不改变门槛。

**M2–M4：始终旁路。**

- 新数据库、无现金影响、无真实下单权限。

**M5：首次接入独立虚拟资金。**

**M6：事件增益独立证明。**

- 真实事件抽取可用与事件交易增益分别结论。
- 无提供商审批时交付完整离线适配与 blocker，不能伪称真实接入。

**M7：交付完整运行证据，不仅截图。**

- 运行手册命令实际验证，故障和恢复结果有记录。

## 12. 运行、持久化与性能

### 12.1 独立存储与写入者

建议新库继续采用：`crypto/work/hybrid_candidate_v1.sqlite3`。

### 12.3 唯一约束与事务

- 原始输入去重键含来源、对象和提供商事件身份；同键不同内容是冲突，不是静默最后写入获胜。
- 技术信号按 §4.3 稳定身份去重，不带变化中的智能快照哈希。
- 评估有自身 ID 和输入版本；旧评估不可覆盖。
- 每 run/实验臂/技术机会最多一个活动入场意图，重复消费不重复扣款。
- 模拟成交事件有独立唯一身份；部分成交累计不能超批准数量。
- 资金、预留、pending、成交、已消费事件、风险引用和 checkpoint 同一短事务提交。
- 提交失败整个组合事务回滚；不在内存先承认成交再期待稍后写库成功。

若诊断报告保存失败，可按研究存储错误记录；若权威账本提交失败，则停止该 writer 的状态推进并告警，不用不同内存状态继续交易。

### 12.4 模型工作器与资源隔离

- LLM 异步、训练离线、后验推断只在新候选时触发。
- MC 工作器数量、队列、内存、CPU、最大路径数和任务期限有界。
- 保护处理拥有独立调度入口，不等待模型 future；模型计算不持有交易事务。
- 新仓积压超过容量时对候选弃权/过期，不让无限重试占满保护资源。
- 先测本机延迟分布再冻结预算，不能凭空保证在 5m 内一定完成。

风险缓存至少绑定：run、portfolio_version、持仓/pending/保护规则、数量网格、时点、历史 manifest、成本、执行代理、风险日、高水位、模型和种子策略。组合变化、日界或成本变化必须使旧缓存失效。

### 12.5 恢复合同

恢复步骤：校验 run manifest → 校验依赖/政策/artifact → 获取本子系统 lease → 读取 checkpoint → 重放未提交唯一事件 → 重建风险与预留 → 确认保护队列 → 才允许新仓。

不得重新请求 LLM 生成旧响应、以“latest”替换原模型或重复消费已提交成交。改变版本需要新 run 或显式迁移。

分别演练：入场已批准未成交、部分成交、已有仓位、待退出无报价、跨日、冷却中、模型未完成、DB 事务回滚、输入重复和恢复后迟到消息。

### 12.6 状态与停止语义

`stop` 不能含糊地等于杀进程。运行手册至少区分：

- `stop-new-entries`：取消待入场/拒绝新仓，保护处理继续。
- `drain`：停止新仓并按原政策持续处理已有虚拟敞口，退出完成后停机。
- `force-stop`：明确中断，包括未退出风险、最后持久状态和恢复要求；需额外确认。

这些是待实现语义，不是已可执行参数。账本/进程故障导致保护无法继续时必须明确告警“保护处理未确认”，不能显示已安全平仓。

超出新仓时效就记录未成交/过期；数学层失败只限制新风险。保护也缺少可信输入时按挂起/告警语义处理，不声称模型失败不影响任何实际风险。

## 18. 完成的定义

完成不是“四个模块都输出一个数”，而是每笔候选都能解释：规则产生什么机会、模型使用什么当时可得信息、数学支持什么结论、风险为什么通过或拒绝、真实虚拟成交何时发生、成本如何进入账本、失败后谁继续保护、结果如何复现。

### 18.1 必须满足的交付条件

- [ ] 当前仓库事实和原 V1.0 的描述已在 M0 区分并核验。
- [ ] Crypto 子系统范围明确，没有顺便重构股票/期权或启用实盘。
- [ ] 原策略、A/B、保护、成本、日界和指标来源已登记；未决项明确阻止对应 PASS。
- [ ] 关闭智能插件及 SHADOW 时，基线逐 bar/逐笔行为一致。
- [ ] 保护通道不等待模型；无有效报价不伪造安全退出。
- [ ] 新仓批次原子性不阻断合法的已有保护处理。
- [ ] 每笔入场都晚于可用数据、评估、提交和允许执行时刻。
- [ ] 所有身份、组合版本、资金预留、成交和 checkpoint 保持幂等与原子性。
