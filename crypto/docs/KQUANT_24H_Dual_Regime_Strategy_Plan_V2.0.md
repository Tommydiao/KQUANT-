## 3. 策略规格：一套状态识别，两套交易规则

策略标识建议为 `crypto_spot_dual_regime_v1.0.0`，注册为研究候选。以下阈值全部为预先提出、尚未验证的设计参数。

### 3.1 时间、指标与初始化

- 状态判断周期：1H；入场和退出回放周期：5m。
- 仅使用当时已经闭合、并在当时可用的数据。状态所用 1H 的结束时间不得晚于 5m 决策时间。
- 1H 指标：EMA50、ER24；ATR14 仅作波动尺度。5m 使用 ATR14 与历史高低价。
- EMA 用 alpha=2/(n+1)，首 n 根的简单均值初始化；ATR 用 Wilder 平滑，首 n 个 TR 的均值初始化。回放与实时使用同一实现。
- 预热至少 250 根连续完整 1H 和 100 根连续完整 5m。预热不计交易，不足或 ATR 非正时禁止新开仓。
- 决策按 UTC 时间存储。页面可转北京时间，不能改变 K 线归属。

效率比 ER24 定义：

`ER24 = abs(C[t] - C[t-24]) / sum(abs(C[i] - C[i-1]), i=t-23..t)`

分母为 0 时 ER24=0。定义 `slope = EMA50[t] - EMA50[t-3]`。

### 3.2 行情状态机

| 状态 | 从过渡状态进入的条件 | 维持条件 | 允许的行为 |
| --- | --- | --- | --- |
| UP_TREND | 连续两根完整 1H 同时满足：C>EMA50，slope>0，ER24≥0.35 | C>EMA50，slope≥0，ER24≥0.25 | 仅允许趋势多头信号 |
| RANGE | 连续两根完整 1H 同时满足：ER24≤0.20，abs(slope)≤0.25×ATR1H | ER24<0.30，abs(slope)≤0.50×ATR1H，冻结箱体仍有效 | 仅允许震荡多头信号 |
| TRANSITION | 初始状态；任一维持条件失败；箱体失效、到期或数据不可用 | 重新累计两根完整 1H 确认 | 禁止新开仓 |

任何可交易状态失效，先进入 TRANSITION 并清零确认计数；不在同一时刻直接从趋势切换为震荡。发生变化的这根 1H 不同时充当重新确认的第一根。

已有仓位保留原入场模式及出场归因。模式失效时，在下一可交易时点退出；不能把亏损趋势单改称震荡单，也不能放宽原止损。下跌或不确定市场采用空仓，不能为了“每天都有交易”降低状态标准。

### 3.3 趋势模块：顺势突破

空仓、无待执行指令、冷却结束且状态为 UP_TREND 时：

1. 当前完整 5m 收盘价 C 严格高于此前 20 根完整 5m 的最高价；突破基准不包含信号根。
2. 止损 S 为最近 6 根完整 5m 的最低价减去 0.25×ATR5m；这 6 根包含信号根。
3. 初始风险距离 d=C−S 必须为正；止盈 T=C+2.5d。
4. 按信号时已知价格与基础成本估计的净目标收益/净止损损失至少为 2.0，才接受信号。
5. 下一可交易时点模拟买入；S、T 在信号时冻结。
6. 触及止损、触及止盈、状态失效或持仓超时即退出。最多持有 72 根 5m，即 6 小时。

第一版不加入分批止盈、移动保本、追踪止损或金字塔加仓，以减少路径歧义和归因难度。计划毛收益风险比为 2.5，但实际平均赢亏比可能更低。

### 3.4 震荡模块：箱体下沿回收，中轴退出

进入 RANGE 时，用包含刚闭合小时在内的最近 24 根完整 1H 冻结：

- 上沿 U=最高价最大值；下沿 L=最低价最小值。
- 宽度 W=U−L；中轴 M=(U+L)/2；冻结当前 ATR1H。
- W 必须为正；箱体最多有效 24 小时。箱体参数在有效期内不随新行情向下移动。

空仓、无待执行指令、冷却结束时：

1. 前一根完整 5m 收盘≤L+0.15W，当前收盘重新上穿这条线，且当前收盘≤L+0.25W。
2. 两根信号 K 线的整个区间都必须位于本次 RANGE 生效之后，不能借进入状态前的数据补出回收信号。
3. 止损 S=L−0.20×冻结 ATR1H；止盈 T=M。
4. 计划毛收益风险比至少 1.8，且按基础成本估计的净比值至少 1.5；空间不够就放弃。
5. 下一可交易时点模拟买入。最多持有 36 根 5m，即 3 小时。

箱体失效优先于新开仓：任一完整 5m 的低点低于 S，或高点高于 U+0.20×冻结 ATR1H，进入 TRANSITION，取消本根新信号。已有保护止损正常执行；其余持仓在下一可交易时点退出。

震荡仓位止损后，当前箱体立即失效。箱体到期后也先进入 TRANSITION，经过两根后续完整 1H 再确认，才能建立新箱体。不能在被跌穿的同一箱体反复抄底。

### 3.5 共用约束

- 每币最多一个持仓，趋势与震荡互斥；禁止加仓摊平和放宽止损。
- 每次退出后，同币冷却 12 根完整 5m；状态确认和冷却条件必须同时满足。
- 信号只在闭合 5m 上生成；同一信号只能处理一次。
- 同一时点多个标的竞争有限仓位时，使用固定顺序 BTC→ETH→SOL，不依据未来收益排序；报告该顺序对成交覆盖的影响。
- 预先存在的保护止损、止盈优先于该根收盘才产生的模式退出或超时指令。
- 无交易也是合法输出，但必须能看见原因：状态不明、未触发、净空间不足、冷却、风险额度不足或数据不可用。

## 4. 成交、成本和仓位契约

### 4.1 可复现的事件顺序

每根 5m 按如下顺序处理：先检查已有仓位开盘跳空触发的保护止损/止盈，再执行此前提交的退出，以及仍符合现金和暂停状态约束的入场；随后处理当根所有仓位的保护止损和止盈；到收盘后更新当时可用的 1H 状态及 5m 指标、日内权益与暂停条件；最后产生下一时点指令。UTC 日界先建立日初盯市权益，再计算当日亏损。风险暂停与模式失效取消尚未成交的入场；保护退出继续有效。

历史入场默认下一根 5m 开盘价加不利执行成本；不能读到下一根开盘后，再事后删除净 RR 变差的交易。资金和数量已在信号时预留；只允许按预先约定的余额、交易所过滤规则拒绝或缩量，并保留拒绝记录。

若入场跳空使成交价已经越过止损或止盈，保留入场记录，再立即模拟平仓，计双边成本。不能无成本撤销这笔亏损可能性。

前向模拟在信号真正可用后，使用收到的第一条有效公共报价：买入以 ask、卖出以 bid，再加预设额外不利滑点。记录数据到达与虚拟成交时间，不能回填为已经过去的下一根开盘。前向保护退出只消费实际虚拟成交之后收到的有效 bid/成交事件；不得使用包含入场前价格的整根 5m 高低点补判止盈止损。历史 OHLCV 回放与前向报价模拟共用决策政策，成交数据来源差异明确标记。

### 4.2 保护价格与同根歧义

- 持仓开盘已向下穿过止损，按更差的开盘价减执行成本退出。
- 持仓向上跳过目标，保守按目标价减执行成本退出。
- 历史回放先处理已知开盘越界；只有开盘尚在止损与目标之间、同一根 5m 又同时触及两者且无法从原始成交序列证明顺序时，才按止损先成交。不能用后来出现的低点推翻开盘时已经成立的目标退出。
- 入场当根也执行同样规则，不能忽略入场后同根止损。
- 历史入场根计第 1 根，完整持有第 72/36 根后在下一开盘退出。前向以实际虚拟成交时间加 6/3 小时为到期时间，随后第一条有效报价退出；数据缺口期间不能虚构成交。
- 回测末尾仓位单独列为“末端强制平仓”，计成本并报告其贡献；不能丢掉浮亏。

### 4.3 成本场景与净 RR

账户实际费率未知，本轮采用以下研究假设，不宣称是用户费率：

| 场景 | 每边手续费 | 历史 OHLCV 每边不利执行成本 | 作用 |
| --- | --- | --- | --- |
| BASE | 10bp | 5bp，作为价差与滑点的合并代理 | 默认验收与信号空间过滤 |
| STRESS_2X | 20bp | 10bp | 手续费及不利执行成本均翻倍的压力测试 |

1bp=0.01%。历史配置字段使用 `ohlcv_execution_cost_bps=5`，包含价差代理。前向使用真实 bid/ask，另设 `quote_extra_slippage_bps=2`，不重复扣价差；前向压力场景将手续费与这项额外滑点分别翻倍，观测价差原样保留。历史与前向的成本场景分别标记。纯成本敏感性报告先固定原信号、逐笔重计成本；再另报完整资金约束下的压力回放，两者不要混在一列。

以信号价 C、止损 S、目标 T、费率 f 和每边不利执行率 s，估算：

`E = C×(1+s)`，`X_target = T×(1−s)`，`X_stop = S×(1−s)`。

`预计净目标收益 = X_target−E−f×(E+X_target)`。

`预计净止损损失 = E−X_stop+f×(E+X_stop)`。

`预计净 RR = 预计净目标收益 / 预计净止损损失`。

分母非正或净目标收益非正时拒绝。实际净盈亏按真实虚拟成交价及双边费用记账，不能直接拿预计净 RR 替代。

回放与前向的信号空间过滤统一使用上述历史成本代理模型，保持决策政策一致；前向实际成本另据报价记录。固定交易成本压力比较沿用 BASE 的初始风险分母，避免换一套 R 分母使压力结果看起来变好。所有成本字段均进入本轮配置与政策哈希。

Binance 官方明确其手续费示例并非实际账户费率，实际费率还涉及账户、交易对与折扣。因此本轮把成本作为显式场景；后续接账户时替换并重算。[官方手续费说明](https://developers.binance.com/en/docs/products/spot/faqs/commission_faq)

### 4.4 虚拟账户风险参数

以下仅为研究模拟的默认预算，不是对用户真实资金的配置建议：

| 参数 | 默认值 |
| --- | --- |
| 初始虚拟资金 | 10,000 USDT |
| 每笔预计止损风险 | 当前盯市权益的 0.25% |
| 同时持仓数 | 最多 2 个，待成交指令同时占额度 |

| 日内亏损触发线 | 相对 UTC 日初盯市权益下降 1%，含浮亏；取消新入场并在下一有效报价退出 |

数量 q 按“0.25% 权益 / 单位预计净止损损失”计算，再取名义上限和可用现金约束的最小值，向下适配交易对数量步长与最小金额。风险阈值是控制目标；跳空、断流和滑点可以造成实际损失超过它，报告必须保留超限。

三个币按同一个相关资产组合管理，不能当作三组独立实验重复计算统计把握。

## 5. 数据计划：先用能证明可用的数据

### 5.1 前 1 小时冻结研究清单

1. 只读检查本地实际 HEAD、未提交改动、采集进程、数据路径和现有运行服务，记录到本轮 manifest。
2. 固定 BTC、ETH、SOL 名单。逐币记录 1H/5m 首尾日期、闭合条数、连续区间、重复、缺口、来源、哈希和读取版本。
3. 优先使用已有 compacted 原生数据；1H 必须覆盖对应的完整 12 根 5m。确需从 5m 聚合时，只允许 12 根连续完整子 K 线构成 1H，不能用部分小时冒充。
4. 历史窗口目标为最近 180 天，已有完整 365 天则保留更长窗口。选择依据是数据可用性和预先规定的日历，不依据哪个区间收益更好。
5. 三币采用相同日历切分。某币不可用时保留排除理由，不悄悄替换成历史表现更好的币。

### 5.2 缺口和前向新鲜度

- 缺失 OHLCV 不通过向前填充制造零波动 K 线；跨缺口重置状态并重新预热。
- 持仓遇到历史缺口，标记路径不可验证，并在下一可见价格作保守退出、计成本；单列这些交易。正式性能验收要求测试区间连续，否则标记数据证据不足。
- 前向预期 5m 收盘超过 30 秒仍无有效闭合数据时，暂停新入场并报告延迟；该阈值是本轮运维参数。
- 已有虚拟持仓继续依据可用报价处理保护退出；若报价也断开，显示“无法估值/无法模拟成交”，不能假定已经止损。
- 恢复后补齐闭合数据并检查顺序，过期信号只写遗漏记录，不追补买入。等待下一根新闭合 5m 才产生新入场。

公共市场数据可以使用 Binance 官方无需 API Key 的只读接口，因此候选行情运行不必等待交易账户接入。[Market Data Only URLs](https://developers.binance.com/en/docs/products/spot/faqs/market_data_only)

### 5.3 两种数据状态分别展示

`candidate_data_eligibility` 逐币判断研究所需预热、完整性、对齐与新鲜度；合格币可研究，缺数据币不能强行运行。

`original_historical_data_gate` 仍按原 31 标的定义计算，并继续显示真实覆盖率。前者合格不修改后者，也不代表执行准入通过。

## 6. 怎样验收“盈亏比很好”

### 6.1 指标定义

| 指标 | 定义 | 能回答的问题 |
| --- | --- | --- |
| 计划毛 RR | (目标价−信号参考价)/(信号参考价−止损价) | 交易设计的价格空间 |
| 实现净盈亏比 payoff | 平均净盈利金额 / 平均净亏损金额绝对值 | 扣成本后赢一笔相对亏一笔有多大 |
| 净 PF | 所有净盈利之和 / 所有净亏损绝对值之和 | 总体赚的钱是否覆盖亏的钱 |
| 净期望 R | 每笔净 PnL /（实际成交数量×信号时冻结的单位预计净止损损失），再对交易求均值 | 单位初始风险的平均结果；不能因跳空亏损而调大分母 |
| 最大回撤 | 逐 5m、含未平仓盈亏和退出成本估计的权益曲线峰谷回落 | 持仓过程承受的损失 |

无赢单或无亏单时，payoff/PF 标记不可估或注明边界，不能把少量全赢样本的 PF 无穷大自动判为合格。额外报告按 R 标准化的 payoff，避免仓位大小掩盖策略质量。

例如净 payoff=2.0 且胜率 40% 时，每笔平均净期望约为 0.2 个平均亏损单位，净 PF 约为 1.33；若胜率降到 25%，净期望就为负。因此不能只优化止盈倍数。

### 6.2 预先写定的研究目标

| 验收项 | 本轮目标 | 失败或不足时的处理 |
| --- | --- | --- |
| 组合实际净 payoff | ≥1.8 | 未达到“高净盈亏比”目标，如实标记 |
| 组合基础成本净 PF | ≥1.30 | 低于 1 直接拒绝；1–1.30 未达标 |
| 组合平均净 R | >0 | 非正则不能宣称盈利优势 |
| 固定交易的双倍成本净 PF | ≥1.05，且完整压力回放净期望>0 | 优势不能覆盖成本压力时未达标 |
| 两种模式分别 | 净 payoff≥1.5，净 PF≥1.25，平均净 R>0 | 一种失败就不能称双模式验证成功 |
| 测试区间组合最大回撤 | ≤5%，并附与原 10R 回撤门槛相同口径的独立结果 | 任一适用门槛失败均保留 |
| 稳健性 | 去掉最佳盈利标的后、去掉最大盈利单后分别重算，净期望仍>0 | 依赖单币或单笔时不进入优势获支持状态 |
| 样本量 | 未参与调参的测试交易合计≥200；每模式≥50；拟声称有效的每 symbol×mode 至少 30 笔 | 这些是必要的样本下限，不等于显著性；不足为证据不足 |
| 不确定性 | 同步日期区块重采样的平均净 R 95% 区间下界>0 | 不能把三币相关交易当独立样本；下界≤0为证据不足 |

以上是本轮研究目标，不降低原正式验证门槛。组合通过不能替代具体 symbol×mode 的证据；弱模式或弱币不能用总体均值遮盖。

### 6.3 防止把旧历史包装成新证据

目前项目已经反复查看历史回测。启动时先登记哪些日期曾用于看结果、选币或调参。已暴露区间的成绩只能作为研发与描述性结果，不能重新切一刀就称为“独立样本外”。

如果确有从未用于开发或筛选的历史区间：在运行结果前固定日历边界，默认最早 70% 用于研发，最新 30% 锁定验收；最终区间再按日历分成 3 个连续报告段。分界前 6 小时禁止新入场，跨界持仓不转移；指标可用过去数据预热，但测试账户空仓开始。三个报告段不重复调参，也不把它们当作互相独立实验。

如果没有真实未暴露区间，明天应报告 `PERFORMANCE_UNPROVEN`，同时交付历史表现和参数冻结后新发生的前向样本。T+8 小时启动的早期前向运行用于验证工程；A/B 选择与最终政策冻结之前发生的前向结果属于开发暴露数据。选择后另开绑定冻结哈希的验收 run，只计其后首次可获得的信号，不能追溯挑选较好的早期成绩。一天前向交易不能凭数量少就推断长期收益或两种行情都已充分出现。

区块重采样按完整 UTC 日期同步保留三币交易，以入场日期归组，默认连续 7 日区块、2,000 次抽样、固定随机种子；少于 12 个完整周区块时说明区间估计不稳定。它用于估计样本不确定性，不能消除已反复调参的历史污染。

多次筛选回测会带来过拟合风险，所以实验次数、失败结果和参数变化都要保留，不能只展示最好的一次。[The Probability of Backtest Overfitting](https://scholarworks.wmich.edu/math_pubs/42/)

### 6.4 只允许两个预登记候选

- A：本文完整基线；趋势目标 2.5d，震荡目标为箱体 50% 位置。
- B：只改变两个目标参数；趋势目标 3.0d，震荡目标为箱体 60% 位置。其他规则、成本和入场净 RR 下限全部不变。
- 候选仅在开发段比较；若都未达到开发筛选目标，不打开最终留出段反复寻找赢家。
- 两者均达到开发筛选目标时，按同步日历开发分段中的最差净 PF 较高者选择；相等选 A。选择及原因在打开最终结果前落盘。
- 最终只对选定候选做一次锁定验收。修复可证实的代码错误后可重跑，但必须记录旧结果失效和修复原因，不能把策略调参伪装为修 bug。
- 预登记两项消融：仅趋势、仅震荡，用于解释两模块贡献；不得据此临时组合出第三套“最佳策略”。

候选结果不得写入原 `crypto_validation_runs`、PAPER、SHADOW 表。原 `latest_validation_run` 存在不按策略过滤的消费者，单纯更换 strategy_version 不足以隔离；明日优先独立数据库。

## 8. 四个工作流并行，避免等待串成一天

T0 为实际开始时间。先用最多 1 小时固定共同契约，再并行实现。人手不足时由主 Codex 依次承担角色，但仍先完成能回放的最小闭环。

| 角色 | 独立负责 | 不得同时修改的共享区域 |
| --- | --- | --- |
| 主 Codex／集成负责人 | 本地基线、配置契约、模式/成交时序、里程碑、集成、最终报告 | 总体配置、manifest、最终合并 |
| 策略代理 | 纯内核、状态切换、信号及确定性场景验证 | 不改 runner、DB 和页面 |
| 数据与验证代理 | 数据 manifest、双周期历史适配、成本回放、指标与报告 | 不改策略规则；发现歧义先反馈契约 |
| 运行与展示代理 | 独立 DB、前向数据消费、恢复/去重、CLI 与简洁面板 | 不改原 EVAL/执行链及主策略参数 |

前三方先共同固定输入快照、决策输出、状态结构和成交事件格式。共享文件由主 Codex 合并，各代理在不冲突文件或隔离工作树实现。每 2 小时更新一次“已完成证据、当前阻塞、下一可见交付”，不能长时间只显示正在思考。

## 10. 最少但必要的验证

| 验证 | 要发现的具体错误 |
| --- | --- |
| 未来数据截断：改变决策时间之后的价格 | 历史决策是否错误依赖未来 1H 或未来入场价 |
| 状态进入、滞回、失效、箱体到期及止损失效 | 两模式同时触发、同箱体反复抄底、亏损单改名续持 |
| 同根止盈止损、跳空、入场当根止损、超时 | 回放是否人为偏向盈利或漏计损失 |
| 双边费用、翻倍压力、资金预留和三币竞争 | 净收益虚高、重复占用现金或风险额度 |
| 同一闭合数据通过回放和前向决策适配器 | 两条路径的决策与原因是否一致；成交差异需有已声明的数据原因 |
| 重复 K 线与中途重启 | 是否重复虚拟成交、丢持仓或重复累计收益 |
| 原 31 标的 gate 仍 NO_GO，合格子集正常研究 | 是否错误阻塞研发，或把原全局状态改成通过 |
| 原 EVAL/PAPER/SHADOW 写入与执行入口调用即失败 | 候选代码是否误入原交易或证据链；仅检查网页路由白名单不够 |
| 新候选结果写入后原 latest validation 不变 | 新研究报告是否污染原策略准入显示 |

测试验证规则和实现；真实市场优势仍需真实数据验证。两种模式的合成行情测试通过，不能代表市场上两种模式都盈利。

## 11. 明日页面和报告必须让用户一眼看懂

页面只需展示：当前模式及原因；最近闭合数据时间；待触发条件；候选信号的入场参考、止损、止盈与预计净 RR；虚拟持仓和净盈亏；趋势/震荡分项表现；最后一次验证状态；原执行模式。

用“候选模拟”明确标注虚拟成交。不要把模型训练状态等实现细节堆入日常操作区；把数据、参数和交易证据放入可展开详情。

最终报告分别给三个判断：

| 维度 | 可能状态 | 判定方式 |
| --- | --- | --- |
| 工程交付 | BUILD_PASS / BUILD_FAIL | 实际启动、回放、前向消费、恢复及必要测试 |
| 候选数据 | ELIGIBLE / PARTIAL / BLOCKED | 逐标的的数据完整性、时序、预热与新鲜度 |
| 策略表现 | TARGET_MET / TARGET_NOT_MET / PERFORMANCE_UNPROVEN | 预登记目标、独立性、样本量、成本和不确定性共同判断 |

同时原样展示原 DATA_GATE、策略 gate、PAPER、SHADOW、Testnet/Live 状态。`TARGET_MET` 仅代表本轮候选研究目标达成，不能直接触发正式下单准入。

## 12. 失败时如何在截止时间内处理

| 情况 | 当天处理 | 明日结果如何表述 |
| --- | --- | --- |
| 一币数据不合格 | 固定名单中合格子集继续；排除原因保留，数据缺口并行修复 | 标明实际只验证了哪些币，不能宣称三币全通过 |
| 三币均没有可用真实历史 | 完成内核和前向真实采集，交付数据阻塞与已运行证据 | 历史性能无法验证，不能用合成成绩补位 |
| 24 小时没有市场触发信号 | 展示持续处理的闭合 K 线、状态、拒绝原因 | 运行正常但前向交易样本为零，不强制开单 |
| 趋势好、震荡亏损 | 双模式判未达标；可另展示趋势单模式研究结果 | 不能称“趋势震荡均有效” |
| 净 payoff 好看但 PF<1 | 检查胜率、成本、跳空及退出原因 | 策略仍亏损，不达标 |
| 历史成绩好但数据曾反复使用或样本少 | 冻结参数，继续收集未来样本 | 性能证据不足，不升级为验证成功 |
| A、B 均失败 | 提供最主要 3 个失败归因及逐笔证据 | 明日交付可运行系统，但高盈亏比盈利目标未完成 |
| 页面阻塞 | 使用已验证 CLI 与报告查看状态 | 用户仍能启动、停止、检查与复现 |

所有失败分支都交付具体结果，不能把目标无限顺延。研究版本可复现是工程成果；是否找到满足用户收益目标的策略，另行如实判断。
