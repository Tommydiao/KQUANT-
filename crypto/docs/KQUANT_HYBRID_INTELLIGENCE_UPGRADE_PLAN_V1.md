## 1. 项目目标与边界

将当前双模式研究候选升级为可解释、可复现、可审计的混合智能研究系统，明确结合：

1. 传统技术分析：识别行情结构，产生具备明确保护价格的候选交易。
2. LLM：将新闻、公告及解释性信息转化为有来源的结构化事件。
3. 贝叶斯分析：估计交易优势，并表达参数与预测的不确定性。
4. 蒙特卡罗模拟：评估给定持仓方案下的组合路径、回撤及尾部风险。
5. 独立风险控制：决定是否允许交易及最大数量，不能被模型绕过。

交付目标是“完整研究与候选模拟闭环”，不是承诺增加 AI 后一定盈利。

### 1.1 本期范围

- 延续 BTCUSDT、ETHUSDT、SOLUSDT 现货研究范围。
- 延续 1H 行情识别、5m 信号触发，上涨趋势与震荡两类做多策略。
- 初期保留原止损、止盈、持仓上限、成本和执行顺序，便于单独归因智能层的贡献。
- 同时支持历史研究、事件回放、公共行情候选模拟及只读展示。
- 新增版本、模型、事件数据与评估记录使用独立命名空间和存储。

### 1.2 本期不做

- 不自动接入实盘，不新增合约空头、杠杆、马丁格尔、摊平或强化学习下单。
- 不重构股票侧，不为升级随意停止公共采集器或原服务。
- 不重写既有不可变回放结果，不把旧数据重新切分后称为未见测试集。
- 不允许 LLM 修改资金、止损、目标价、风险限额、执行准入或配置文件。
- 不把已存在的研究模块改名后直接宣称“训练完成”或“概率已校准”。

```text

                         |
                         v
             原始数据与首次可用时间层
                         |
              +----------+-----------+
              |                      |
              v                      v
        技术特征快照           LLM 事件提取工作器
              |                      |
              |                结构化事件仓库
              +----------+-----------+
                         |
                当时可用的特征快照
                         |
             原双模式技术候选信号内核
                         |
                  贝叶斯交易评估
                         |

                         |
             蒙特卡罗组合风险评估
                         |
               确定性决策与独立风控
                         |
             原有候选模拟成交与组合账本
                         |

```

边界原则：

- 网络、数据库、LLM 请求位于适配器或工作器，不进入纯策略内核。
- 数学评估输出结构化结果，不直接写入交易账户。
- LLM 事件提取异步运行；交易时只读取已经完成且未过期的事件快照。
- 贝叶斯和蒙特卡罗不是四个指标投票中的两个票，不对其输出简单加权求“总分”。
- 规则模式与贝叶斯状态后验分开命名；初期只有原状态机决定 `UP_TREND/RANGE/TRANSITION`。
- 原版本与智能版本分别维护组合状态；不能共用会互相污染的现金、冷却或待成交指令。

## 5. 数据与时间合同

### 5.1 统一时间字段

对市场、事件、模型分别保存：

| 字段 | 含义 |
| --- | --- |
| `event_time` | 市场或新闻事件实际发生时间，可未知 |
| `published_at` | 来源声称的发布时间，不等于系统已收到 |
| `received_at` | 本系统首次接收时间 |
| `available_at` | 完成必要处理后首次可用于决策的时间 |
| `decision_time` | 本次决策实际运行时间 |
| `signal_time` | 触发所对应的 5m 收盘时间，沿用旧内核合同 |
| `label_available_at` | 训练标签首次完整可知的时间 |
| `model_available_at` | 训练、校准与登记全部完成的时间 |

统一以 UTC 存储；适配器可采用毫秒以保留报价到达顺序，旧 `Bar.start` 仍为整数秒。

必要不变量：

```text
bar.start + 300 <= decision_time
hourly.start + 3600 == signal_time（仅该小时刚闭合时提供）
所有特征 available_at <= decision_time
模型 model_available_at <= decision_time
训练标签 label_available_at <= model_training_cutoff
LLM 事件 available_at = max(首次收到时间, 推理完成时间, 校验完成时间)
```

在任何现金、指令、日界或模型状态变更之前校验整个 batch；不同标的应共享同一个闭合时间。未来数据、不对齐、冲突重复和倒序输入应原子拒绝。

旧 `PointInTimeFeatureSnapshot` 使用 `available_at <= signal_time` 的合同，与候选模拟中信号收盘后才真正收到信息的情况不同。新增智能快照显式区分收盘时间和决策时间，不能简单改写旧字段或伪造提前可用。

### 5.2 数据质量与失败处理

- 维持 250 根连续完整 1H、100 根完整 5m 预热；缺口后重新预热。
- 每根 1H 必须由完整 12 根 5m 证明；有量能特征后同时核对成交量。
- 历史 candle-close 可用性是研究假设，实际接收时间证据另列。
- 新闻更正、撤回、来源冲突按追加版本处理，不能覆盖当时决策看到的版本。
- 没有历史可用时间的新闻不得混入严格时点回测。
- 新闻未出现、新闻源断流、LLM 失败必须是三种不同状态，不能都编码为“中性”。
- 当前交易所过滤规则用于历史回放继续明确标记代理假设。

### 5.3 LLM 历史知识污染

今日模型可能已经知道历史事件的后果。即使只输入旧新闻，也不能据此证明它在历史时点没有未来知识。

处理方式：历史 LLM 结果只作开发性实验；抽取只允许引用输入证据，不让模型自由补充市场后果；正式证明 LLM 增益依靠参数和提示词冻结之后的新发生前向样本。

## 6. 数学规格

所有新增数值均为研究设计，不宣称已获得盈利验证。数学规格必须先于实现冻结，代码与合成边界测试一一对应。

### 6.1 技术分析保持原定义

```text
EMA_n(t) = alpha*C_t + (1-alpha)*EMA_n(t-1), alpha=2/(n+1)
EMA 首 n 根用简单均值初始化。

TR_t = max(H_t-L_t, |H_t-C_(t-1)|, |L_t-C_(t-1)|)
ATR_14(t) = [13*ATR_14(t-1)+TR_t]/14
首 14 个 TR 用均值初始化；第一根 TR 使用 H-L。

ER_24(t) = |C_t-C_(t-24)| / sum(i=t-23..t, |C_i-C_(i-1)|)
分母为零时 ER=0。
slope_t = EMA_50(t)-EMA_50(t-3)
```

趋势突破、六根止损窗口、冻结箱体、两小时确认和失效顺序完全沿用旧规格。本阶段不同时重写技术规则，以免无法解释增益来自哪里。

### 6.2 成本与标签

以信号参考价 C、止损 S、目标 T、每边手续费 f、执行代理 s 定义：

```text
E = C*(1+s)
X_stop = S*(1-s)
X_target = T*(1-s)
L_net = E-X_stop+f*(E+X_stop)
G_net = X_target-E-f*(E+X_target)
expected_net_rr = G_net/L_net
R_net = 实现净盈亏 / (实际数量 * 信号时冻结的 BASE L_net)
```

BASE 与压力成本、bid/ask 和额外滑点继续按原合同，不能双扣价差。压力风险预算采用压力预计净损失，但净 R 分母不随压力或实际亏损扩大。

标签通过共享成交规则生成，包含止损、止盈、超时、模式失效、缺口和末端清算归因。目标先触及、净收益为正、平均收益为正是不同问题，不共用一个标签。

保存全部规则候选信号，包括被组合额度或模型拒绝的信号。可为被拒绝信号生成独立的假设单笔结果，但必须标记 `counterfactual_label`，不计入真实模拟成交数或组合收益。

重叠信号、同日多币不是独立样本；同源候选需关联组 ID，统计时按时间区块处理依赖性。没有完整未来观察窗口的标签标记删失/不可用，不得当作零收益或亏损。

### 6.3 贝叶斯：先建立可解释的收益模型

V1 主模型建议为分层 Student-t 净 R 回归，而不是把固定行情状态概率直接映射为交易胜率：

```text
R_j ~ StudentT(nu, mu_j, sigma_mode)
mu_j = alpha_mode + u_symbol,mode + beta_mode^T*x_j + eta_day(j)
u_symbol,mode ~ Normal(0, tau_mode^2)
eta_day = phi*eta_previous_day + epsilon_day
epsilon_day ~ Normal(0, omega^2), |phi|<1, nu>2
```

其中 x 只使用当时可知且在训练段拟合变换的特征。分层收缩用于小样本组；共享日期项表达同日及跨币关联，但不宣称能够完全消除所有重叠交易依赖。

建议起始先验：标准化特征上的 beta 为以零为中心的收缩先验，组均值以零净优势为中心，尺度参数为正分布。具体尺度、nu 和 phi 的先验必须通过先验预测检查后在 M1 冻结，不能根据最终测试收益修改。

初版技术特征上限建议 8 个，例如 ER、ATR/价格、归一化均线斜率、突破距离、箱体位置、量能变化、BTC 相对收益、ETH 相对收益。模式不适用字段使用明确缺失掩码。LLM 事件特征后续作为预登记扩展，不与第一轮混合调参。

预测必须区分：

```text
p_win(x) = P(R_new > 0 | x, D)
mu(x) = E[R_new | x, D]
p_edge(x) = P(E[R_new | x, theta] > 0 | D)
q05_mu(x) = 后验均值收益分布的 5% 分位数
```

`p_edge` 描述均值优势的后验可信程度，不等于下一笔获利概率；后验可信区间不等于频率学置信区间。

未来日期隐变量不能使用未来交易结果估计；在线预测使用当时可得的条件预测分布。V1 冻结 run 内不自动再训练，训练完成后才产生新 artifact；后续增量训练另立版本和验证。

诊断应包含先验/后验预测检查、收敛与有效样本诊断、概率校准、先验敏感性、时间分段和不同标的表现。后验预测的基本形式与实现校验依据见 [Stan 后验预测文档](https://mc-stan.org/docs/stan-users-guide/posterior-prediction.html)。

### 6.4 贝叶斯准入建议

先旁路记录全部预测，不影响交易。达到模型验证门槛后，新的智能政策才允许用 `q05_mu > 0` 过滤候选；连续分布下这与约 95% 的正均值后验可信程度一致，不把它们当两份独立证据。

上述 95% 是待 M1 预登记的研究阈值，不是已验证的最优参数，也不是原 A/B 策略的新规则。缺样本、诊断失败、模型过期或输入越界时输出 `ABSTAIN`。

贝叶斯模型应输出真实计算得到的结果，不能把正则化模型的一个点估计命名为后验分布。推断使用成熟概率编程工具，具体依赖先在隔离环境验证，不升级公共采集运行环境。

### 6.5 蒙特卡罗：区分三类问题

| 模拟 | 输入与方法 | 允许解释的结论 |
| --- | --- | --- |
| 研究不确定性 | 同步日期区块重采样真实交易/组合记录 | 历史指标的不确定性；不是新交易证据 |
| 候选组合风险 | 同步多币 5m 市场路径，评估已有仓位、待成交与拟新增仓位 | 未来有限期限内、给定假设下的风险分布 |
| 人工压力场景 | 跳空、滑点扩大、相关性上升、报价中断 | 脆弱性与损失上界情景；不能附未经估计的发生概率 |

V1 组合风险模拟采用只含过去数据的同步多币区块抽样，不能分别打乱 BTC/ETH/SOL，也不能先删除非目标行情再把不相邻片段当连续历史。

采样单位保存整段 OHLC 相对变化，例如开盘相对上一收盘、high/open、low/open、close/open；在新路径重建合法 OHLC，保持跨币同一时间块，禁止从收盘插值虚构高低点。

风险模拟从当前组合和实际尚未成交的计划出发，保留保护价格、剩余持有时间、现金、日期与成本。初版只评估现有及拟加入风险，不假设未来还会出现哪些 LLM 新闻或新入场。因此不递归调用蒙特卡罗，不把虚拟新闻搬到重采样价格路径上。

初版建议期限为未来 6 小时，覆盖当前最长持仓；1 日和 7 日扩展另行报告并注明“无后续新开仓”等假设。默认离线 5,000 条路径作为起点，路径数、区块长度、历史窗口需做数值稳定性检查后冻结。

```text
V_t = cash_t + sum_s(q_s,t * 可退出标记价格_s,t - 预计退出费用_s,t)
MDD_h = max(t<=h, 1 - V_t / max(u<=t, V_u))
Loss_h = (V_0 - V_h)/V_0
P_breach = count(模拟路径中触及指定风险线)/N
VaR_alpha = Loss_h 的 alpha 分位数
ES_alpha = 最大 (1-alpha) 比例损失的平均值
```

ES 使用确定的尾部排序与边界插值口径，概率同时附蒙特卡罗数值误差；零次观察到损失不等于真实概率为零。增加路径数不能弥补短历史或错误模型。

初版可以显示 `P(MDD_6h>1%)`、ES95、回撤分位数；建议研究性仓位约束为 `P(MDD_6h>1%)<=5%`，正式使用前必须完成校准和 M1 预登记。

重要：区块 bootstrap 不自动等于完整贝叶斯后验预测。V1 中贝叶斯估计信号优势、蒙特卡罗独立估计路径风险，接口组合但不伪称同一个联合概率模型。若后续要传播全部参数不确定性，应另建并验证联合市场生成模型，按 theta~p(theta|D) 后再采样路径，不能把净 R 后验与价格收益重复叠加。

### 6.6 仓位与决策

```text
q_base = min(
    单笔风险预算/当前成本场景的单位预计止损损失,
    剩余组合风险预算/单位预计止损损失,
    标的名义上限/预计单位买入支出,
    未预留可用现金/预计单位买入支出
)
q_final = 向下适配交易所步长(q_base * m)
m 属于预登记的 {0, 0.25, 0.5, 1}
```

风险模块逐个检查离散数量，不假设有费用、最小金额和非线性退出规则时风险必然严格单调。初期只能拒绝或缩量，不能超过原风险预算。三币竞争沿用 BTC、ETH、SOL 固定顺序。

执行准入顺序：数据合格、原技术信号合格、贝叶斯可用且通过、模拟风险合格、独立硬风控与现金合格。所有拒绝记录结构化原因。

原独立风控继续采用：单笔 0.25%、组合预计风险 0.50%、最多两仓、单币名义 25%、日亏损 1%、连续三亏暂停两小时。保留跳空超限事实，不通过调整分母掩盖。

## 7. LLM 接入设计

### 7.1 两个权限明确的用途

1. 事件提取：输入允许来源的文档，输出涉及资产、事件类型、时间、证据、冲突及缺失信息。
2. 解释生成：根据已经冻结的数值决策与证据，生成中文说明；解释失败不改变订单或风险状态。

事件类型初期限定为公告、网络运行事件、交易服务异常、已发布的重大宏观事件等有限 schema。新增来源和类型都要登记；没有真实授权来源时返回 `SOURCE_UNAVAILABLE`，不用模型编造新闻。

### 7.2 结构化输出合同

```text
event_id, schema_version, source_id, document_hash,
published_at, received_at, extraction_finished_at, available_at,
symbols, event_type, factual_claims, evidence_spans,
conflicts, uncertainty_reasons, expires_at,
provider, model_id, prompt_hash, output_hash, status
```

禁止输出具有执行权限的 `buy/sell` 指令、仓位、止损、收益承诺或配置变更。`factual_claims` 必须能定位到输入原文；模型自报置信度不能直接转换为交易成功概率。

### 7.3 时延、失败和缓存

- 文档内容哈希、模型身份、提示词和 schema 共同决定缓存键；缓存保存原始响应与校验结果。
- 温度为零也不承诺远端推理逐次完全一致；历史复现使用冻结输出，不重新请求生成。
- LLM 不在每根 5m 临时阻塞请求；事件工作器完成后更新可用快照。
- 推理超时、限流、额度用完或校验失败时不追补已过去的交易。
- 技术旁路实验可以继续无 LLM 的基线；已启用 LLM 特征的候选遇到强制事件源失效，默认停止新入场，而不是默默切回另一套政策。

### 7.4 安全与成本

外部新闻和模型输出都视为不可信数据。LLM 工作器不授予 shell、数据库写入原证据表、交易密钥、交易 API 或任意网络工具权限。权限隔离与输出校验是主防线，不能只依赖提示词。设计参考 [OWASP 提示注入防护](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。

先完成离线 fixture 适配器；真实提供商、模型标识、凭据和每日费用上限经用户确认后再启用。提供商选择看事件抽取准确性、延迟、隐私与成本，不默认购买订阅或多模型并行调用。

验收用人工标注事件集，分别报告类型/资产识别、时间抽取、证据支持率、弃权率、攻击样本表现和每事件成本。LLM 解释通顺不能代替事实准确。

### 8.1 建议接口

```python
build_feature_snapshot(market, events, decision_time) -> FeatureSnapshot
predict_posterior(snapshot, model_artifact) -> PosteriorPrediction
simulate_portfolio_risk(portfolio_snapshot, proposed_plan, history, config) -> RiskForecast
evaluate_candidate(signal, prediction, risk, policy) -> DecisionAdjustment
```

`DecisionAdjustment` 仅允许 `ACCEPT/REJECT/ABSTAIN`、不超过 1 的数量比例、原因和证据引用。不得携带新的止损/目标价格。

评估接口放在原技术信号产生之后、现金和风险正式预留之前。不得先预留后因模型不喜欢而无记录删除；模型延迟后再读下一开盘筛掉坏交易也是禁止的。

无插件或旁路模式必须逐 bar 重现基线决策、交易、数量和权益。智能插件不能让纯内核跳过已有持仓期间的状态更新。

## 9. 训练与防泄漏验证

1. 先登记历史曝光日历；现有已暴露历史只能做开发与描述性评估。
2. 使用按日历向前推进的训练、校准、评估分区，不随机打乱行。
3. 以标签信息区间清除跨边界重叠样本；对最长 6 小时结果标签至少保留对应间隔，并按实际延迟扩展。
4. 标准化、缺失处理、特征选择、概率校准和阈值选择都只能访问所属训练/开发窗口。
5. 参数、先验、提示词、特征和筛选方案都算实验，全部进入实验账本。
6. 只有训练完成且登记后模型才可以服务后续时点。历史模拟也要表示训练完成时间，不能零延迟使用未来拟合结果。
7. 测试最终完整组合表现，同时报告按标的、模式、日期和事件类型分拆结果。

时间序列拆分需要防止未来训练、过去评估；通用 `TimeSeriesSplit` 可作工具参考，但不能代替交易标签重叠清除及已暴露数据审计。见 [官方时间序列拆分说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。

### 9.1 最少实验矩阵

在已冻结 A/B 政策中，按原流程选定基础政策；若两者均失败，只能选择明确标注“研发参考”的基线，不能称赢家。

| 实验 | 用途 |
| --- | --- |
| T | 原技术策略，固定规则基准 |
| T+B | 仅贝叶斯过滤，验证信号筛选贡献 |
| T+M | 仅蒙特卡罗风险缩量，验证风险贡献 |
| T+B+M | 验证两数学层组合 |
| T+B+M+L | 加入 LLM 事件特征，验证信息增益 |

上述是预登记归因实验，不是允许从大量组合中挑最高收益。完整模型与去掉 LLM 的对照保持相同训练窗口、风险预算与成本。另报告现金基准，防止“全部拒绝、零回撤”被误判为成功。

每个需要评估的版本保留 BASE、固定交易双倍成本，以及完整压力资金回放。不得混淆这三类成绩。

## 10. 测试与验收矩阵

| 测试层 | 必须验证 |
| --- | --- |
| 技术内核 | 原全部状态、失效、预热、窗口、冷却测试保持通过 |
| 时间与原子性 | 未来 bar/hour/news/model、不同步 batch 在状态变更前拒绝；重复与乱序不产生新交易 |
| 成交 | 下一开盘、开盘越界优先、同根止损优先、入场当根止损、quote 按 bid、跳空双边成本 |
| 日界风险 | 23:55 旧日亏损先判、待退出保留、实际新开盘建立基准、保护退出优先 |
| 标签 | 6h/3h 期限、模式失效、删失、缺口、反事实与真实交易隔离 |
| 贝叶斯数学 | 解析小例子、先验预测、后验预测、推断诊断；模拟校准不能代替真实预测验证 |
| LLM | schema、证据、重复新闻、撤回、断流、提示注入、虚构、预算和超时 |
| 蒙特卡罗 | 同种子复现、不同种子误差、多币同步、OHLC 合法、费用、极端情景、无递归 |
| 组合 | 两仓、现金预留、缩量上限、三币顺序、压力 sizing 与 BASE R 分母 |
| 恢复 | pending/持仓/冷却/模型/事件水位原子恢复，版本不同拒绝，已保存响应重用 |
| 隔离 | 原 EVAL/PAPER/SHADOW/执行模块用抛异常替身后，新研究流程仍可运行 |
| 兼容 | 关闭智能插件时与当前修正后基线逐笔一致 |
| 集成 | 历史与前向使用同一决策，成交数据差异有记录；数据库事务失败停止写入 |

先运行受影响测试；关键集成点再运行 Crypto 必需回归。不要反复启动无关股票测试或重启采集服务。测试通过只证明对应实现行为，不证明市场盈利。

### 10.1 四类验收独立展示

- `ENGINEERING_STATUS`：实现、测试、启动、恢复及隔离是否通过。
- `DATA_STATUS`：连续性、可用时间、新闻覆盖与前向新鲜度是否合格。
- `MODEL_STATUS`：未训练、诊断失败、未校准、旁路观察、可用于候选模拟。
- `PERFORMANCE_STATUS`：目标达到、目标未达到或证据不足。

模型诊断和校准不能只凭 AUC；需要 Brier/对数损失、校准图、区间覆盖、净 R 误差与样本量说明。无足够样本不显示稳定概率结论。

### 10.2 收益与风险研究门槛

除非另行明确审批，不降低原研究计划要求：组合净 payoff>=1.8、BASE PF>=1.30、平均净 R>0、固定交易双倍成本 PF>=1.05、完整压力回放净期望>0、组合最大回撤<=5%，并保留原适用 10R 门槛。

两模式分别报告原门槛；独立测试实际交易合计至少 200、每模式至少 50、拟声称有效的 symbol×mode 至少 30。它们是必要下限，不是充分统计证明，也不能用重叠反事实标签凑数。

同步日期区块下的平均净 R 区间、去掉最佳标的和最大赢家的敏感性继续保留。蒙特卡罗生成的 5,000 条路径不增加真实市场样本量。

## 12. 运行、持久化与性能

建议新数据库：`crypto/work/hybrid_candidate_v1.sqlite3`；输出：`crypto/outputs/hybrid_regime_v1/<run_id>/`。不共享旧候选正在运行的 writer lease。

新增表或事件类型：feature_snapshots、event_extractions、model_artifacts、posterior_predictions、risk_forecasts、decision_adjustments、training_runs。表名带新版本命名空间，交易和预测通过 ID 关联。

候选信号唯一键包含版本、政策、标的、模式、信号收盘与输入快照身份。资金、pending、成交、已消费事件、模型身份、风险结果引用和 checkpoint 在同一事务提交。

性能设计：LLM 异步、训练离线、模型推断只在新信号时运行；组合模拟使用有界工作器和缓存，缓存绑定组合、时间、成本、输入与模型哈希。先测量本机容量再冻结延迟预算。

超出决策新鲜度窗口时记录“未成交/过期”，不能把结果回填到过去开盘。数学层失败只停止新开仓，已有保护退出继续运行。

报告需要列出被拒绝信号与拒绝原因，避免只展示成功交易；分模式、分币、分事件、分日历段评价，不掩盖弱模块。

## 14. 发布、回退与保护

- 当前策略和采集进程继续运行；先做独立旁路，再启用隔离候选账户。
- 旧 A/B 结果、各次修正 run、冻结数据与更正记录保持不可变。
- 新模型导致异常时停新入场，保持保护退出；不能把智能仓位直接改名为旧版仓位。
- 回到技术基线需显式新 run 或预登记迁移事件，不能在同一个收益序列中静默换策略。
- 数据库迁移仅作用于新库；写入失败时停止该 writer，不循环重放已成交事件。
- 实盘属于本计划之外的独立审批：需经过原策略版本对应的验证、PAPER/SHADOW/Testnet 等适用准入，不由本计划自动开启。

## 18. 完成的定义

完成不是“四个模块都能输出一个数”，而是：每笔候选交易能解释四个模块各自做了什么，每个输出有当时可用的数据与版本依据，全部成本和风险真实记入模拟账本，任何模块失败都不越权，并且能够明确回答系统是否比固定技术基线更可靠、收益证据是否足够。

在这些条件成立之前，系统始终是研究候选，不作收益保证，也不获得自动实盘资格。
