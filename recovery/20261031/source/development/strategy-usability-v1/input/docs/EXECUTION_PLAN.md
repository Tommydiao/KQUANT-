## 5. T2：幅度诊断——先记录，不增加硬门槛

对合法5m计算：

```
range_bps = 10000*(H-L)/O_session
body_bps = 10000*abs(C-O)/O_session

```

辅助历史确实可用时，再计算：

```
range_vs_same_slot_median = (H-L) / median(previous 20 valid sessions' same-slot ranges)
range_vs_prior_atr = (H-L) / prior_session_ATR14
```

同时间段历史不足、ATR未知或分母为0时返回null和支持数量，不补零，也不阻塞S0/S1已可执行的核心计算。滚动窗口只用事件前数据；复权价格、原生价格、币种须可比。

**上述指标仅做DIAGNOSTIC_ONLY。**本轮不把range太小、gap太大、IV高等任意判断新增为硬门，不增加综合“Alpha分数”。排序沿用既有确定性方式；对新字段的人工排序不改正式策略筛选。

- A：O=100,H=100.05,L=99.99,C=100.04。
- B：O=100,H=105,L=99,C=104。

两者M=2/3、Q=5/6，但range分别0.06和6。页面不能因为M/Q相同就宣称同样获利空间。

### 6.2 必须显示的成本诊断

设a为ask、b为bid、m为已核验的合约乘数；行情价格与费用币种一致、0<=b<=a且mid>0才计算：

```
spread = a-b
spread_pct_mid = spread / ((a+b)/2)
premium_cash_reference = a*m
spread_cash_reference = spread*m
spread_equivalent_underlying_move = spread / abs(delta)
```

最后一项名称是“仅Delta局部近似下抵消当前价差所需正股变化”，**不是到期盈亏平衡价，不是目标价，也不是未来获利预测。**Delta为0、未知或过时则不算。

若当前授权费用/滑点定义可用，再显示：

```
round_trip_cost_per_unit = spread + slippage_in + slippage_out + (fee_in+fee_out)/m
cost_equivalent_underlying_move = round_trip_cost_per_unit / abs(delta)
```

费用未知时仍显示价差项，完整成本为null；不默认零佣金。bid/ask已经包含价差，不能在净差后又扣一次。

固定数学例：b=2.40,a=2.60,m=100,delta=0.5。显示权利金260、仅价差20、相对支出7.6923%、价差等效股价移动0.40；这些都是TEST_ONLY算术，不是市场报价或交易。

### 6.3 复用已有Greeks工具作确定性说明

只在输入单位和现有工具适用范围清楚时使用：

```
dV_local = delta*dS + 0.5*gamma*dS^2 + vega*dIV_pp + theta*elapsed_calendar_days
```

可支持用户输入或预登记的小幅变化场景；必须显示“局部近似、条件假设、非成交价”。Vega单位为IV百分点与实现一致，Theta按自然日，分时使用是近似而不是已验证的精确日内损耗。

不新增美式定价大工程；已有适用的重定价工具可复用，缺股息/利率/适用性则标明。不得从当天Greeks外推确定的长期利润，不给场景分配未经验证的概率。理论价值不能当exit bid。

**成本诊断目前不作为新硬门。**结论可以是“规格合格，估值优势未知”，不能自动写“便宜/值得买”。后续只有数据支持、明确新协议和接受后，才讨论成本敏感的选择政策。

### 7.3 明确本轮主要标签，不伪造完整退出策略

主研究问题：**两套筛选后的事件，人工反应后60分钟的正股方向性变化和路径怎样？**这不是自动策略收益，也不替代用户的退出动作。

研究主延迟=60秒；30/120秒为预登记敏感性。它们是研究测量设定，不改变生产信号deadline。

```
t_ready = 首次冻结合格技术快照实际可用/提交时刻
reference_time_target = t_ready + delay
```

历史只有1m时，使用不早于target的下一个有完整记录的1m开盘作为PRICE_OBSERVATION_PROXY，记录其真实时刻；严格在原300秒及10:00前，同时检查既有入场/追价区间。错过即MISSED_REFERENCE_WINDOW，不移后deadline，不补当天过去时间。

主标签：以参考时刻后60分钟的正股观测计算方向收益；仅当60分钟不跨既有最晚管理时刻且路径完整时，计入标准60分钟队列。提前收市/绝对时点截短单独标HORIZON_TRUNCATED。

```
y60_pct = d*(P60-P0)/P0, d=+1(Call),-1(Put)
y60_structure_units = d*(P60-P0)/R0
MFE60 = max(0, max[d*(P(t)-P0)])/R0
MAE60 = max(0, max[-d*(P(t)-P0)])/R0
```

使用路径中与方向匹配的高低价，参考时点前的bar不得混入；结构R0为正股距离，不是金额风险。MFE不是可实现利润；同bar先后未知标注PATH_ORDER_UNKNOWN。主要不模拟止损先后成交，避免OHLC假顺序。

另保存原结构失效时点、60分钟不足0.5R的复核标记、原最晚管理时间。1R后如何收紧如本地已有唯一规则就引用；缺明确规则则退出政策细节为UNRESOLVED，**不临时发明一种追踪止损来生成PnL**。用户自报仍为人工自报，不填订单或Paper成交。

有匹配的同合约后续bid/ask时，可另做指定时点的报价代理结果：

```
quote_proxy_change = multiplier*(exit_bid-entry_ask)-known_fees
```

必须标明固定观察时点、价格代理、不保证成交、不是原策略真实退出。原费用/额外滑点如何纳入保持唯一口径；费用缺失不给“净”结果，未知单位不猜。只有正股时，不输出期权胜率、PF或“盈利策略”。

- 不做新模型训练、阈值搜索或指标堆叠。幅度诊断的分组边界只能来自开发段，留出段不能调整。
- 报告日期覆盖、候选率、延迟后可观察率、y60均值/中位、MFE/MAE、结构失效及成本支持。单位必须明确；Call/Put、Core/非Core及资产类型分别列。
- 同股跨点、同日多股票具有相关性；区块不确定性应按日期对齐，样本不足仅描述，不声称统计独立。当前自选回测历史须披露选择和幸存者偏差。
- 只有S1候选多，不构成采用S1的理由。结论只能是增益有待验证/无明显增益/数据不足/值得下一轮预登记，不能自动晋级。

## 8. T5：实际Signal页面改什么

复用当前Signals入口和详情，不重做全站。

每张卡至少显示：

| 区域 | 内容 |
|---|---|
| 研究身份 | S0基准/S1研究、策略hash、数据方法、检查点和实际available_at |
| 条件差异 | M/Q、当日方向、昨收方向通过/失败/未知/不需要、突破与结构 |
| 幅度 | range_bps、可用的归一化幅度；无历史不消失 |
| 合约 | 准确代码、right、expiry、strike、DTE、真实bid/ask及各自年龄 |
| 成本 | 参考权利金、价差现金、完整成本是否已知、Delta等效位移及限制 |
| 状态 | 技术研究触发/待合约/参考合约/原严格合格/失效；不合并成一个BUY |
| 后续 | 已过有效期、尚未到标签时刻、60分钟结果、来源缺失分别展示 |

默认仍显示完整自选及当前研究，不再只有合格卡空白；可切S0/S1差异视图。同一经济机会合并卡，不做两个相同提醒。

S1有依据但只有参考报价时，卡片应写“研究候选，非合格买入提示”；单位缺失只使金额字段未知；成本诊断缺失不抹掉技术结果。报价过3秒移除当前可操作外观，保留带原时间的参考信息；不能刷新页面给旧报价续期。

卡片没有胜率和预期净利润时，保持null；不加入“AI信心”或90分来替代缺失证据。手工自报已有许可继续原行为，不自动生成新持仓。

## 9. T6：先交一个真实贯穿样例，再做一次最终集成验收

### 最小穿透测试

使用已有真实FCX/NVTS等记录，以同一生产评价/存储/API/前端链展示：S0因真实缺口未完成、S1在其日内输入确实齐全时通过或未触发。不能预先要求它们一定给出正Signal。

已知相同条件差异的正例可以使用隔离TEST_ONLY，至少包含Call和Put；这证明代码能走通，不作市场证据。

第二步获取当前真实参考合约，或如实显示接口/规格缺口；同一标的失败不得卡住所有对象。至少一个非Core实际自选进入网页研究路径，不能用NVDA一例认证全量。

### 版本与运行分开

- 已接受观察载荷与新开发工作树分开。只有源码/规则/解析方法等有实质变化的部分进入新候选，不将每条动态行情都当成需要重新签整个程序。
- 原始数据、快照、测量与结果追加保存；不能因它们自然变化让一次测试误报业务源码漂移。方法/权限变化仍需准确接受。
- 正常服务不为等待研究结果停止；若已停止，安全观察版的真实装配验收不以取得完整S0为前置。
- 必要测试经过真实入口、Supervisor构造/run、共享角色映射与实际编译前端。外部传输用测试替身要显式标记，不能替换整段生产调用链。
- 原HTTP、队列、3秒/60秒/300秒门槛不随意放宽。研究回放离线执行，不抢占采集writer或用户持仓处理。
- 最终一次匹配混合小时复用已有工具，加入S0/S1、缺昨收、分钟修订、三个页面、合约不可用及带pending的恢复。不每天对不变源码重跑小时消耗全部开发时间。

## 10. T7：交付、一次接受及持续观察

### 第一个可用版本，2—3个开发工作日投入检查点

这是工作量检查点，不是保证自然信号、盈利或外部资料按期取得。

先交：S0/S1纯计算与正反例 → 实际网页差异/成本 → 真实历史有限回放与全量状态 → 匹配候选和运行验收。任务阶段内连续执行，不逐项等用户说继续。

继续既有O-LAUNCH：一次提交准确候选、研究方法、实际页面测试和已知缺口，用户接受研究显示/影子运行；旧正式合格权限不被新S1借用。已有P14来源方法待决项只提出真正影响本次功能的差异，不重复旧审批。

在用户已接受观察的准确版本上，使用原调度采集下一适用交易日。计算时间使用America/New_York，显示Asia/Shanghai；不能复用10月14日等已经过去的计划日期。未运行记NOT_RUN；没有数据记DATA_UNAVAILABLE；真实完整计算后未触发才记NO_TRIGGER。

首5个实际观察日沿用O-OPS5，检查运行和用户体验；第20日生成证据报告，不需每个小任务再生成新计划。这不是后台工作承诺，必须有已存在且获准的普通调度；不存在就交明确手动启动/恢复命令。

### 本轮验收交付物

1. 准确S0 hash和S1唯一规则差异、必要输入依赖表。
2. 可运行页面：S0/S1差异、具体参考合约、成本和未知原因。
3. 一份有限回放报告：共同可比集与S1独立可算集分开。
4. 实际引用的输入、输出和label样例；未来结果仍未成熟时不补造。
5. 匹配候选、原入口、真实状态、负载与恢复证据。
6. 恢复指针与现有任务状态，不再交一份“建议以后做”的空计划。

### 明确停止规则

同一外部缺口最多一次精确诊断和一次条件改变后的复测；没有新事实则转独立分支。2—3个工作日后仍只有新增审批/校验、没有真实页面研究结果，应提交一个具体需要替换/隔离的模块与最小决定，不自动再开十几个修复任务。

不以必须出现盈利、200筆交易或全部111身份变绿作为研发结束线；但有真实合法输入时却始终全INCOMPLETE，应当判为设计/实现未交付，不能归咎市场。

## 11. 关键验收例（完整机器清单见plan/acceptance_tests.json）

- 同一共同输入只改变昨收方向门：跳空下跌后上涨的Call、跳空上涨后下跌的Put，S0/S1出现预期差异。
- S0必要输入齐全且通过时，S1技术结果不能失败；严格不等式边界按原规则处理。
- 昨收未知时S0 INCOMPLETE，S1可以按有效日内输入计算；报表不把此类写成S0否决的增量收益。
- 当日开盘未知、当前bar未闭合/来源冲突/非法OHLC时，S1不能因较少依赖硬过。
- 辅助ATR/20日量能缺失不阻断核心计算；零振幅不能除零。
- 合约乘数、单位或费用未知只影响对应成本字段；参考不能升格合格。
- 成本例按260/20/0.40核对；同一价差不能重复扣。
- 标签采用后续时点，人工延迟不续期；MFE不当可实现PnL；部分退出/实际自报不被研究标签改写。
- 分页、旧Core与自选分组不限制全量；同一事件双版本不重复通知/SDK请求。
- 数据或worker失效立即显示对应状态；新合法修订原截止内重算，旧结果留档。
- 无来源、单源时钟问题与API额度不足按用途分级，不改已有方法成通过。
- 新研究记录不写旧qualified_claims、订单或Paper；无自然候选也能验证工程正反路径。
