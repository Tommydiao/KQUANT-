# 跨电脑接续办法

用户已确认：换电脑后当前电脑不能继续保持开机联网。因此本次及近期采用“两台电脑各保留基础工程，后续传增量”，换机时由另一台电脑接续本地工作。

| 办法 | 换电脑时的工作量 | 适用情况 |
|---|---|---|
| 固定电脑运行，远程连接 | 不搬项目文件；连接原电脑上的工作环境 | 原电脑能保持开机、联网，且允许远程访问 |
| 两台电脑各留基础工程，传增量 | 首次约 295 MB 基础包；之后只取新增内容 | 原电脑会关机，或需要各自在本地工作 |
| 云端主机运行 | 配置一次服务器，之后远程访问 | 长期需要持续运行，愿意承担服务器配置和费用 |
| Codex Cloud 开发任务 | 先连接代码仓库、准备环境和导入资料；之后从其他设备继续同一云端任务 | 后续代码开发和测试，须另行验证项目数据与依赖 |

## 以后如何减少交接

固定运行电脑能直接保留文件、依赖和运行状态，是避免反复下载最直接的办法。当前电脑已核验为 Windows 11 Pro；微软远程桌面支持从另一台设备访问应用与文件，作为被连接端需要 Pro。开机、网络可达和远程连接配置还须实际确认，目前没有改动这些设置。

官方说明：[微软远程桌面](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/how-to-use-remote-desktop)、[远程连接前提](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access)。

如果两台电脑都要独立运行，则保留各自的基础工程，通过版本清单传源码和资料的增量。活动 SQLite 留在本地；交接时导出一致性快照，云端同步快照归档。每次切换只在一台机器上继续写入，避免两个不同进度相互覆盖。

本次先完成夸克增量交接。当前电脑无法保持在线，远程续作不适用于今天；未来若有固定在线机器，再评估远程主机或服务器方案。

## Codex Cloud 是否能替代搬文件

2026-10-07 已查阅官方资料：Codex Cloud 常规设置从连接 GitHub 仓库开始，准备并发布云端环境；已有云端任务可以继续使用它自己的已保存文件和工具，本机休眠时仍可工作。它不会因此自动接收当前本机的项目目录。

官方资料：[Cloud 环境及保存状态](https://learn.chatgpt.com/docs/environments/cloud-environments)。另有独立的 [Agents API 文件入口](https://developers.openai.com/api/docs/guides/agents-api/environments/files)，需要 API 和应用配置，不能视作本机 Cloud 按钮已经上传完成。

本项目当前仍在本地工作区，尚未迁入 Codex Cloud。若以后选该方案，需要先把代码纳入适当的私有仓库、准备依赖、另行导入数据库快照和历史分钟资料，并重新核验恢复。云端开发任务的保存状态与持续运行行情服务的部署分别验证；今天先交付已经实际恢复验证过的基础包和增量。

对于上百 GB 数据，官方当前列出的 Cloud 任务默认磁盘：Plus / Edu Plus 为 8 GiB，Pro / Business / Enterprise / Edu / Edu Pro 为 32 GiB；Enterprise 可联系 OpenAI 另配更大规格。默认 VM 保存状态可恢复至最后开始一轮或恢复任务后的 7 天。故普通 Cloud 任务不承担上百 GB 长期归档；大量历史行情仍另存，云端任务按需取用有限数据。依据同一官方页面的 [VM specifications](https://learn.chatgpt.com/docs/environments/cloud-environments#vm-specifications)。
